## 1. 목적

국내에서 오래 쓰인 알집 형식(ALZ) 파일을 받으면 7-Zip으로는 열 수 없어 다른 프로그램을 설치해야 한다. j-zip은 ALZ를 다른 형식과 같은 방식으로 열고 풀 수 있게 한다. 만드는 기능은 제공하지 않는다. EGG는 지원하지 않는다(9절).

## 2. 현재 7-Zip 동작

- `CPP/7zip/Archive` 아래에 ALZ 핸들러가 없음. `"alz"` 문자열 검색 결과 0건 (`7z/7zUpdate.cpp:723`의 확장자 정렬 목록에도 없음).
- 사용자 입장: `.alz` 파일을 7-Zip으로 열면 아카이브로 열 수 없다는 오류가 남. 우클릭 메뉴의 풀기 항목도 동작하지 않음.

## 3. 요구사항

- FR-07-1 `.alz` 파일을 S1에서 열면 다른 아카이브와 같이 S1-13 트리와 S1-14 목록에 내용이 보인다.
- FR-07-2 형식 판별은 확장자가 아니라 파일 시그니처로 한다. 확장자가 다른 ALZ도 열려야 한다.
- FR-07-3 S2, S7-01, S7-02, 무결성 테스트(S1-06)가 ALZ에서도 다른 형식과 같이 동작한다.
- FR-07-4 S1-21 상태 줄의 형식 칸에 "ALZ"와 압축 방식을 표시한다. S1-14 형식 배지도 같다.
- FR-07-5 암호가 걸린 항목은 S1-14에 암호 아이콘을 표시하고, 풀 때 S6를 띄운다. 지원하지 않는 암호 방식이면 S9-02에 "지원하지 않는 암호 방식"으로 표시하고 나머지 파일은 계속 푼다.
- FR-07-6 지원하지 않는 압축 방식의 항목은 해당 항목만 실패로 처리하고 S9에 표시한다. 아카이브 전체를 실패시키지 않는다.
- FR-07-7 ALZ에 파일 추가·삭제·이름 변경(#14), 새로 만들기는 제공하지 않는다. S1-04, S1-05는 비활성 + 툴팁("이 형식은 읽기만 가능").
- FR-07-8 파일명 인코딩 정보가 없는 항목은 #17(F17)의 감지 규칙을 따르고, S1-12·S2-10을 표시한다.
- FR-07-9 MSIX 매니페스트 `uap:FileTypeAssociation`에 `.alz`를 넣고, S8-07 연결 프로그램 목록에 표시한다.

## 7. 구현 지점

- `7z.dll`에 새 핸들러 `CPP/7zip/Archive/AlzHandler.cpp`를 만들고 `REGISTER_ARC_I`(읽기 전용)로 등록.
- ALZ: unalz(원본 C++, **zlib License**)를 `third_party/`에 소스 동봉하고 `IInArchive` 핸들러로 감싼다. unalz는 구형(2009년 이전) ALZ만 지원한다([07. 기술 스택](../07-tech-stack.md) 7절).
- `CPP/7zip/Bundles/Format7zF/makefile`의 `AR_OBJS`에 추가. (research 자료: Format7zF makefile 내용 자체는 열어 보지 않음.)
- 고지: unalz(zlib) 고지를 `THIRD_PARTY_NOTICES.md`에 넣는다.

## 9. 범위 밖·미결 사항

- 범위 밖: ALZ 만들기, 수정.
- EGG는 지원하지 않음(사용자 결정, 2026-10-14) — 반디집 공식 목록에도 없음; 열기 시도 시 "지원하지 않는 형식" 안내.
- 해결: ALZ는 unalz(zlib, LGPL 호환 허용형)를 동봉한다(07 문서 7절). 법률 자문은 아니다.
- 미결: 지원할 압축 방식·암호 방식의 범위. 조사 자료(Bandizip 도움말) 기준 ALZ = Deflate, Obfuscated Deflate, bzip2 변형, ZipCrypto, 분할. unalz가 지원하지 않는 신형 ALZ 처리 방식(`alkegi/unalz`(MIT) 참고 여부)도 정해야 한다.
- 미결: ALZ의 파일명 인코딩(코드페이지 고정인지, 유니코드 표시가 있는지)과 분할 볼륨 이름 규칙은 확인되지 않았다.
- 해결: 06 S1-12·S2-10의 표시 조건을 "항목 이름에 인코딩 정보가 없고(ZIP UTF-8 플래그 없음, ALZ 등) 그중 ASCII가 아닌 이름이 있을 때"로 넓혔다(FR-07-8).
