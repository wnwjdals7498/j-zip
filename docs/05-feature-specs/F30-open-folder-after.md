## 1. 목적

압축을 푼 뒤 사용자는 대부분 결과 폴더를 직접 찾아 들어간다. 해제가 끝나면 만들어진 폴더를 탐색기로 바로 열어 주고, 원하지 않으면 끌 수 있게 한다.

## 2. 현재 7-Zip 동작

- `UI/GUI`, `UI/Common`, `ProgressDialog2.cpp`에서 `ShellExecute`나 `SHOpenFolderAndSelectItems` 검색 결과 0건. `ShellExecute`는 `AboutDialog.cpp`, `BrowseDialog2.cpp`에만 있다 (research #30).
- 진행창은 오류가 없으면 `CProgressDialog::OnExternalCloseMessage`(`ProgressDialog2.cpp:991-1047`)에서 `End(0)`로 바로 닫힌다 (research #32). 사용자에게는 진행창이 사라지는 것 외에 아무 일도 일어나지 않는다.

## 3. 요구사항

- FR-30-1 S2에 "끝나면 폴더 열기"(S2-06)를 둔다. 기본값은 S8-02의 값이며, 처음 설치 시 켜짐이다.
- FR-30-2 S4에 같은 체크박스(S4-05)를 두고 S2-06 값을 이어받는다. 진행 중에 바꾸면 이번 작업 결과에만 적용한다.
- FR-30-3 S7-01, S7-02, S7-10처럼 S2 없이 시작한 해제는 S8-02의 저장값을 쓴다.
- FR-30-4 해제가 오류·경고 없이 끝나고 S4-05가 켜져 있으면 탐색기로 결과 위치를 연다. 여는 대상:
  - 해제로 새 폴더가 하나 만들어졌으면(스마트 #13의 "폴더 만듦", "항상 이름 폴더") 그 폴더를 연다.
  - 폴더 없이 풀었으면(스마트의 "그대로", "폴더 없이") 풀 위치를 열고 새로 만든 최상위 항목을 선택한다.
- FR-30-5 여러 아카이브를 한 번에 풀면(#35, 대기열 S4-07) 마지막 작업이 끝난 뒤 한 번만 연다. 모든 결과가 같은 상위 폴더에 있으면 그 폴더를 열고 결과 항목들을 선택한다. 상위 폴더가 서로 다르면 첫 결과의 상위 폴더만 연다.
- FR-30-6 같은 폴더를 이미 연 탐색기 창이 있으면 새 창을 만들지 않고 그 창을 앞으로 가져온다.
- FR-30-7 취소된 작업, 오류·경고가 있는 작업은 자동으로 열지 않는다(S9가 대신 뜬다).
- FR-30-8 S4-10 완료 알림의 "폴더 열기" 버튼은 S4-05 값과 관계없이 FR-30-4와 같은 대상을 연다.
- FR-30-9 테스트(S1-06, S7-06)와 압축(S3)에는 적용하지 않는다.

## 5. 동작 규칙과 예외

- 결과 폴더가 그 사이에 지워졌거나 옮겨졌으면 열지 않고, S4-10의 "폴더 열기"를 누른 경우에는 "폴더를 찾을 수 없음 · 이동했거나 삭제됨" 안내를 띄운다.
- 풀 위치가 네트워크 경로이고 연결이 끊겼으면 열기를 건너뛴다(오류 대화상자 없음).
- #31(원본 휴지통)과 함께 켜져 있으면, 휴지통 이동 후 폴더를 연다. 순서가 바뀌어도 결과 폴더는 영향받지 않는다.
- #32에서 진행창이 자동으로 닫히는 경우에도 폴더 열기는 실행된다.
- S1에서 드래그로 꺼낸 경우(#11)는 사용자가 놓은 위치가 이미 보이므로 적용하지 않는다.

## 7. 구현 지점

- 완료 후 실행: `JZip.exe`의 해제 완료 처리(S4)에서 결과 위치를 연다. 현재 완료 지점의 근거는 `CPP/7zip/UI/GUI/ExtractGUI.cpp` `CThreadExtracting::ProcessWasFinished_GuiVirt`(94행)·`ExtractGUI()`(167행) 끝, `CPP/7zip/UI/FileManager/ProgressDialog2.cpp` `CProgressDialog::OnExternalCloseMessage`(991행) (research #30).
- 옵션 UI: `JZip.exe`(WinUI 3) S2-06·S4-05·S8-02를 새로 만든다. 기존 파일 `CPP/7zip/UI/GUI/ExtractDialog.cpp` `OnInit`(137행)/`OnOK`(299행), `ExtractDialogRes.h`, `ProgressDialog2Res.h`는 근거로만 쓴다 (research #30, #32).
- 저장: `jzip-core` 설정(기존 `CPP/7zip/UI/Common/ZipRegistry.h` `NExtract::CInfo` 기반, research #30).
- 컨텍스트 메뉴 경로: `jzip-shell.dll` → `JZip.exe --extract …`(현재 `UI/Common/CompressCall.cpp:255` `ExtractArchives` → 7zG `x`, research #12). `JZip.exe`가 S8 저장값을 읽는지, 실행 인자로 넘길지는 9절 미결.

## 8. 수용 기준

- [ ] `D:\test\사진_2026.zip`(최상위 항목 5개)을 S2 기본값(스마트, 끝나면 폴더 열기 켜짐)으로 풀면 끝난 뒤 `D:\test\사진_2026\` 탐색기 창이 열린다.
- [ ] 최상위 폴더가 `report\` 하나뿐인 `report.zip`을 스마트로 `D:\test`에 풀면 `D:\test` 창이 열리고 `report` 폴더가 선택돼 있다.
- [ ] S2-06을 끄고 풀면 탐색기 창이 열리지 않는다.
- [ ] 진행 중 S4-05를 끄면 끝나도 열리지 않고, 다음 해제의 S2-06 기본값은 바뀌지 않는다.
- [ ] `a.zip`, `b.zip`, `c.zip`을 같은 폴더에서 선택해 S7-10 "각각 폴더로 풀기 (3개)"를 실행하면 탐색기 창이 1개만 열리고 `a`, `b`, `c` 폴더가 선택돼 있다.
- [ ] `D:\test` 탐색기 창을 열어 둔 상태에서 같은 위치로 풀면 새 창 대신 기존 창이 앞으로 온다.
- [ ] CRC 오류가 있는 ZIP을 풀면 폴더가 열리지 않고 S9가 뜬다.
- [ ] 해제 중 취소하면 폴더가 열리지 않는다.
- [ ] S8-02에서 끄고 S7-01 "여기에 풀기"를 실행하면 폴더가 열리지 않는다.

## 9. 범위 밖·미결 사항

- 범위 밖: 결과 폴더를 S1에서 여는 옵션, 압축 후 결과 파일 위치 열기.
- 미결: S7에서 시작한 `JZip.exe` 해제가 S8 설정을 직접 읽을지, `jzip-shell.dll`이 새 실행 인자로 넘길지. research 자료에는 #31용 CLI 스위치 추가만 언급돼 있다.
- 미결: FR-30-5에서 상위 폴더가 서로 다른 경우의 처리(첫 위치만 열기)는 임시 규칙이다. 사용자 테스트 후 확정한다.
