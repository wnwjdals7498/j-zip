## 1. 목적

압축 시간을 줄이려면 여러 CPU 코어를 써야 한다. 7-Zip은 이미 스레드 수 선택을 제공하므로, j-zip은 기본값을 "자동"으로 두고 일반 사용자는 신경 쓰지 않게 하며, 고급 사용자만 고급 패널에서 바꾸게 한다.

## 2. 현재 7-Zip 동작

- 컨트롤 `IDC_COMPRESS_THREADS` (`CPP/7zip/UI/GUI/CompressDialogRes.h:15`), `CompressDialog.cpp:486`에서 연결.
- 형식별 허용 여부는 `g_Formats[]`의 `kFF_MultiThread` 플래그 (`CompressDialog.cpp:238` 정의). 플래그가 있는 형식: 7z, Zip, BZip2, xz (`:286`, `:294`, `:308`, `:315`). GZip, Tar, wim에는 없음.
- 형식이 바뀌면 `MultiThreadIsAllowed`를 갱신하고 콤보를 활성/비활성함 (`CompressDialog.cpp:711-714`). 스레드 목록은 `SetNumThreads()`가 채움 (`:704`), 선택 값은 `GetNumThreadsSpec()`으로 읽음 (`:1144`).
- 사용자 입장: 압축 대화상자에 항상 스레드 콤보가 보이고, 기본은 자동 값.

## 3. 요구사항

- FR-03-1 S3-10의 "CPU 스레드" 기본값은 "자동 (N / M)"이다. N = 자동으로 쓸 스레드 수, M = 논리 CPU 수. 자동 값 계산은 7-Zip `SetNumThreads()` 규칙을 그대로 따른다.
- FR-03-2 S3-02가 "간단"이면 스레드 선택은 숨겨지고 자동 값이 적용된다.
- FR-03-3 S3-04 또는 고급 패널의 형식이 `kFF_MultiThread`가 없는 형식(GZip, Tar, wim)이면 "CPU 스레드"를 비활성화하고 이유 툴팁("이 형식은 한 코어만 사용함")을 보여 준다.
- FR-03-4 사용자가 고른 스레드 수는 S3-11 "기본값으로 저장"을 켰을 때만 다음 기본값이 된다.
- FR-03-5 스레드 수를 바꾸면 S3-06 예상 시간이 갱신된다.

## 5. 동작 규칙과 예외

- 스레드 수를 늘리면 메모리 사용량도 늘어난다. 7-Zip은 메모리 사용량을 계산해 너무 크면 경고한다(`IDS_MEM_ERROR`, `CompressDialog.cpp:1062` 부근). j-zip은 이 검사를 유지한다.
- TAR.GZ 카드(S3-04)는 gzip 단계가 단일 스레드이므로 스레드 선택이 비활성이다.
- 압축 중 우선순위 낮추기는 S4-08 "백그라운드로"에서 다룬다(#32).
