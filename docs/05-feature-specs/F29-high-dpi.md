## 1. 목적

4K 노트북에 일반 모니터를 연결해 쓰는 경우처럼 모니터마다 배율이 다르면, 시스템 DPI만 인식하는 7-Zip 창은 비트맵 확대로 흐려진다. Per-Monitor V2 DPI 인식과 벡터(또는 배율별) 아이콘으로 100–300% 어느 배율에서도 선명하게 보이게 한다.

## 2. 현재 7-Zip 동작

- `CPP/7zip/UI/FileManager/7zFM.exe.manifest:17`, `CPP/7zip/UI/GUI/7zG.exe.manifest:17`에 `<dpiAware>true</dpiAware>`가 있다. 이는 System DPI aware 모드다 (research #29).
- `PerMonitorV2`, `GetDpiForWindow`, `WM_DPICHANGED`, `LOGPIXELSX` 검색 결과 0건 (research #29).
- 툴바는 BMP 2벌(`resource.rc:170` `IDB_ADD` Add.bmp, `:177` `IDB_ADD2` Add2.bmp). 큰 버튼 토글은 `IDM_VIEW_TOOLBARS_LARGE_BUTTONS` (`App.cpp:263-270` `LargeButtons`) (research #29).
- 사용자 입장: 로그인 시 주 모니터 배율로는 선명하지만, 배율이 다른 모니터로 창을 옮기면 Windows가 비트맵으로 늘리거나 줄여 글자·아이콘이 흐려진다.

## 3. 요구사항

- FR-29-1 7zFM, 7zG는 Per-Monitor V2 DPI 인식으로 동작한다.
- FR-29-2 창이 배율이 다른 모니터로 이동하면(`WM_DPICHANGED`) 창 크기, 글꼴, 여백, 열 폭, 아이콘을 새 배율로 다시 계산한다. 06 문서 2절의 레이아웃 값(px)은 100% 기준이며 배율을 곱해 쓴다.
- FR-29-3 툴바·메뉴·목록·상태 줄 아이콘은 벡터 원본에서 만들거나 100/125/150/200/250/300% 배율별 비트맵을 준비해, 어느 배율에서도 확대 보간 없이 그린다.
- FR-29-4 아이콘은 디자인 파일의 선 아이콘 형태(툴바 22px, 작은 아이콘 16px, 100% 기준)를 따른다. 반디집 아이콘을 쓰지 않는다.
- FR-29-5 아이콘 색은 테마 토큰(`text`, `muted`, 툴바 기본 버튼은 흰색)을 따라 라이트/다크(#28)에서 모두 보인다.
- FR-29-6 S2–S9 대화상자도 열린 모니터의 배율로 그린다. 대화상자를 열어 둔 채 모니터를 옮겨도 잘리거나 겹치는 컨트롤이 없다.
- FR-29-7 기존 "큰 버튼" 토글(`IDM_VIEW_TOOLBARS_LARGE_BUTTONS`)은 배율과 별개로 유지하거나, 06 문서 C05(높이 56, 아이콘 22 + 라벨) 하나로 통일한다(9절 미결).

## 5. 동작 규칙과 예외

- 셸 확장(S7)은 탐색기 프로세스 안에서 돌아가므로 DPI 모드는 탐색기를 따른다. 메뉴 아이콘(C22, 16px)은 탐색기가 알려 주는 배율에 맞는 크기를 돌려준다.
- 비클라이언트 영역(제목 표시줄)은 Per-Monitor V2에서 시스템이 자동으로 조정한다.
- 아이콘 리소스를 바꿔도 다국어 번역 파일(#22)의 문자열 ID는 바꾸지 않는다.
- 배율 변경 중 창 크기 재계산이 반복되지 않도록 `WM_DPICHANGED`가 제안하는 사각형을 그대로 쓴다.

## 7. 구현 지점

- 매니페스트: `CPP/7zip/UI/FileManager/7zFM.exe.manifest`, `CPP/7zip/UI/GUI/7zG.exe.manifest`에 `<dpiAwareness>PerMonitorV2</dpiAwareness>` 추가 (research #29). 셸 확장 DLL(`CPP/7zip/UI/Explorer/7-zip.dll.manifest`)은 대상이 아니다(9절, research 자료도 이에 맞게 고침).
- 툴바: `CPP/7zip/UI/FileManager/App.cpp` `CreateToolbar`/`AddButton`, `LargeButtons`(`:263-270`) (research #29).
- 비트맵 리소스: `CPP/7zip/UI/FileManager/resource.rc:170`(`IDB_ADD`), `:177`(`IDB_ADD2`) 등 (research #29).
- `WM_DPICHANGED` 처리 위치(창 프로시저, 대화상자 기본 클래스)는 research 자료에 구체적인 함수가 없다. `CPP/Windows/Control/Dialog.cpp`가 후보다(#28과 같은 파일).

## 8. 수용 기준

- [ ] 100% 모니터와 200% 모니터를 연결하고 S1을 100% → 200% 모니터로 옮기면, 툴바 아이콘이 44px(22 × 2)로 선명하게 그려지고 글자가 흐리지 않다.
- [ ] 같은 상황에서 S2를 열어 둔 채 옮겨도 "풀 위치" 입력 칸과 "찾아보기…" 버튼이 겹치지 않는다.
- [ ] 125%, 150%, 175%, 250%, 300%에서 S1 툴바·목록 아이콘에 계단 현상이나 번짐이 없다(화면 캡처 확대로 확인).
- [ ] 작업 관리자 "DPI 인식" 열에 7zFM.exe와 7zG.exe가 "모니터별(v2)"로 표시된다.
- [ ] 다크 테마(#28)에서 툴바·트리·상태 줄 아이콘이 배경과 구분된다(대비 3:1 이상).
- [ ] 200% 모니터에서 S1-14 열 폭을 조정하고 100% 모니터로 옮긴 뒤 다시 실행해도 열 폭 비율이 유지된다.

## 9. 범위 밖·미결 사항

- 범위 밖: 아이콘 세트 전면 재디자인 외의 브랜딩 작업, 파일 형식별 아이콘(탐색기 연결 아이콘)의 재제작.
- 해결: research 자료의 `Explorer/7-zip.dll.manifest` 변경 지점은 삭제했다. DLL은 탐색기 프로세스에 로드되므로 DLL 매니페스트로 프로세스 DPI 모드를 바꿀 수 없다. 이 파일은 현재 Common-Controls 의존성만 선언하고 `dpiAware` 항목이 없다. 셸 확장 쪽은 아이콘 크기 대응만 하면 되는지 확인이 필요하다.
- 미결: 아이콘 원본 형식(SVG → 빌드 시 배율별 PNG/BMP 생성, 또는 아이콘 글꼴) 결정.
- 미결: `IDM_VIEW_TOOLBARS_LARGE_BUTTONS`와 "텍스트 라벨 표시" 같은 기존 툴바 옵션을 유지할지(FR-29-7). 06 문서 C05는 아이콘 + 라벨 한 가지만 정의한다.
- 미결: Win32 유지 vs WinUI 3 결정(02 문서 4절)에 따라 작업 범위가 크게 달라진다.
