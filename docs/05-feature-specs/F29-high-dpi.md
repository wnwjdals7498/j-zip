## 1. 목적

4K 노트북에 일반 모니터를 연결해 쓰는 경우처럼 모니터마다 배율이 다르면, 시스템 DPI만 인식하는 7-Zip 창은 비트맵 확대로 흐려진다. j-zip은 WinUI 3 앱 `JZip.exe`의 모니터별 DPI(Per-Monitor V2) 기본 지원과 벡터(또는 배율별) 아이콘으로 100–300% 어느 배율에서도 선명하게 보이게 한다([07. 기술 스택](../07-tech-stack.md) 7절).

## 2. 현재 7-Zip 동작

- `CPP/7zip/UI/FileManager/7zFM.exe.manifest:17`, `CPP/7zip/UI/GUI/7zG.exe.manifest:17`에 `<dpiAware>true</dpiAware>`가 있다. 이는 System DPI aware 모드다 (research #29).
- `PerMonitorV2`, `GetDpiForWindow`, `WM_DPICHANGED`, `LOGPIXELSX` 검색 결과 0건 (research #29).
- 툴바는 BMP 2벌(`resource.rc:170` `IDB_ADD` Add.bmp, `:177` `IDB_ADD2` Add2.bmp). 큰 버튼 토글은 `IDM_VIEW_TOOLBARS_LARGE_BUTTONS` (`App.cpp:263-270` `LargeButtons`) (research #29).
- 사용자 입장: 로그인 시 주 모니터 배율로는 선명하지만, 배율이 다른 모니터로 창을 옮기면 Windows가 비트맵으로 늘리거나 줄여 글자·아이콘이 흐려진다.

## 3. 요구사항

- FR-29-1 `JZip.exe`(7zFM·7zG를 대체)는 Per-Monitor V2 DPI 인식으로 동작한다. WinUI 3 앱의 기본 동작을 그대로 쓰고 매니페스트에서 낮추지 않는다.
- FR-29-2 창이 배율이 다른 모니터로 이동하면 창 크기, 글꼴, 여백, 열 폭, 아이콘이 새 배율로 다시 그려진다. 06 문서 2절의 레이아웃 값(px)은 100% 기준 유효 픽셀(epx)로 XAML에 그대로 쓰고, 배율 계산은 WinUI 3(`XamlRoot.RasterizationScale`)가 한다. 직접 픽셀을 다루는 곳(썸네일 #26 등)만 `RasterizationScale`을 곱한다.
- FR-29-3 툴바·메뉴·목록·상태 줄 아이콘은 벡터 원본에서 만들거나 100/125/150/200/250/300% 배율별 비트맵을 준비해, 어느 배율에서도 확대 보간 없이 그린다.
- FR-29-4 아이콘은 디자인 파일의 선 아이콘 형태(툴바 22px, 작은 아이콘 16px, 100% 기준)를 따른다. 반디집 아이콘을 쓰지 않는다.
- FR-29-5 아이콘 색은 테마 토큰(`text`, `muted`, 툴바 기본 버튼은 흰색)을 따라 라이트/다크(#28)에서 모두 보인다.
- FR-29-6 S2–S9 대화상자도 열린 모니터의 배율로 그린다. 대화상자를 열어 둔 채 모니터를 옮겨도 잘리거나 겹치는 컨트롤이 없다.
- FR-29-7 7zFM의 "큰 버튼" 토글(`IDM_VIEW_TOOLBARS_LARGE_BUTTONS`)은 따라 만들지 않고, 06 문서 C05(높이 56, 아이콘 22 + 라벨) 하나로 통일한다.

## 5. 동작 규칙과 예외

- 셸 확장 `jzip-shell.dll`(S7)은 탐색기 프로세스 안에서 돌아가므로 DPI 모드는 탐색기를 그대로 물려받는다. DLL이 DPI 모드를 정하지 않으며, 메뉴 아이콘(C22, 16px)만 탐색기가 알려 주는 배율에 맞는 크기로 돌려준다(`GetIcon`).
- 제목 표시줄은 WinUI 3 창이 배율에 맞춰 조정한다.
- 아이콘 리소스를 바꿔도 번역 리소스(#22)의 문자열 키는 바꾸지 않는다.
- 창 크기·위치 기억(06 문서 5절)은 유효 픽셀 기준으로 저장해, 다른 배율 모니터에서 다시 열어도 같은 크기로 보이게 한다.

## 7. 구현 지점

- `JZip.exe`(WinUI 3): 모든 화면(S1–S9, D1–D3)을 유효 픽셀 기준 XAML로 만든다. DPI 처리 코드를 따로 두지 않는다.
- 아이콘: 툴바·목록·상태 줄 아이콘을 벡터(XAML 경로·아이콘 글꼴) 또는 배율별 PNG 자산(`scale-100`~`scale-400`)으로 `JZip.exe`에 넣는다. MSIX 앱 아이콘·파일 형식 아이콘도 배율별 자산으로 만든다.
- `jzip-shell.dll`: `GetIcon`(`CPP/7zip/UI/Explorer/ContextMenu.cpp:1664` 기반)이 배율에 맞는 아이콘을 돌려준다.
- 7-Zip 기존 파일은 고치지 않는다. `7zFM.exe.manifest`·`7zG.exe.manifest`(`<dpiAware>true</dpiAware>`), `App.cpp` `CreateToolbar`/`LargeButtons`(`:263-270`), `resource.rc:170`·`:177` 비트맵은 현재 동작 근거일 뿐이다 (research #29).

## 8. 수용 기준

- [ ] 100% 모니터와 200% 모니터를 연결하고 S1을 100% → 200% 모니터로 옮기면, 툴바 아이콘이 44px(22 × 2)로 선명하게 그려지고 글자가 흐리지 않다.
- [ ] 같은 상황에서 S2를 열어 둔 채 옮겨도 "풀 위치" 입력 칸과 "찾아보기…" 버튼이 겹치지 않는다.
- [ ] 125%, 150%, 175%, 250%, 300%에서 S1 툴바·목록 아이콘에 계단 현상이나 번짐이 없다(화면 캡처 확대로 확인).
- [ ] 작업 관리자 "DPI 인식" 열에 `JZip.exe`가 "모니터별(v2)"로 표시된다.
- [ ] 다크 테마(#28)에서 툴바·트리·상태 줄 아이콘이 배경과 구분된다(대비 3:1 이상).
- [ ] 200% 모니터에서 S1-14 열 폭을 조정하고 100% 모니터로 옮긴 뒤 다시 실행해도 열 폭 비율이 유지된다.

## 9. 범위 밖·미결 사항

- 범위 밖: 아이콘 세트 전면 재디자인 외의 브랜딩 작업, 파일 형식별 아이콘(탐색기 연결 아이콘)의 재제작.
- 해결: research 자료의 `Explorer/7-zip.dll.manifest` 변경 지점은 삭제했다. DLL은 탐색기 프로세스에 로드되므로 DLL 매니페스트로 프로세스 DPI 모드를 바꿀 수 없다. `jzip-shell.dll`은 탐색기의 DPI를 물려받고 아이콘 크기 대응만 한다.
- 미결: 아이콘 원본 형식(SVG → 빌드 시 배율별 PNG 생성, XAML 경로, 또는 아이콘 글꼴) 결정.
- 해결: `IDM_VIEW_TOOLBARS_LARGE_BUTTONS`·"텍스트 라벨 표시" 같은 7zFM 툴바 옵션은 따라 만들지 않는다. 06 문서 C05(아이콘 + 라벨) 하나만 둔다(FR-29-7).
- 해결: UI 기술은 WinUI 3로 확정했다(02 문서 4절, 07 문서). `WM_DPICHANGED` 직접 처리와 Win32 매니페스트 변경은 범위에서 빠졌다.
