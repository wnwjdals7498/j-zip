## 1. 목적

여러 압축 파일을 받았을 때 하나씩 풀면 번거롭다. 7-Zip에 이미 있는 "각각 이름 폴더로 풀기"를 그대로 쓰되, 메뉴 문구를 알아보기 쉽게 바꾸고 폴더를 만들지 여부는 #13 스마트 규칙을 따르게 한다. 새로 만드는 동작은 없다.

## 2. 현재 7-Zip 동작

- `CPP/7zip/UI/Explorer/ContextMenu.cpp:832-834`: 여러 개를 고르면 `specFolder = '*'`이고 "Extract to `*\`" 항목을 만든다(857-866행) (research #35).
- `CPP/7zip/UI/Common/Extract.cpp:70-76`: `NExtractOutDirMode::k_ReplaceAsterisk`로 `*`를 아카이브 이름으로 바꾼다 (research #35).
- 여러 아카이브는 `CompressCall.cpp` `ExtractGroupCommand`로 한 번에 넘어간다 (research #35).
- 폴더가 섞여 있으면 메뉴가 숨겨진다(`areDirs`, 800-804행). 실행 시에는 `IDS_SELECT_FILES` 오류(1280행) (research #35).
- 사용자 입장: `a.zip`, `b.zip`을 고르고 "Extract to `*\`"를 누르면 `a\`, `b\` 폴더에 각각 풀린다. 아카이브 안에 이미 최상위 폴더가 하나 있어도 폴더가 한 겹 더 생길 수 있다(중복 루트 폴더 제거는 #13의 `ElimDup` 조건에만 해당).

## 3. 요구사항

- FR-35-1 아카이브를 2개 이상 고르면 S7-10 "각각 폴더로 풀기 (N개)"를 최상단에 표시한다. N은 선택한 아카이브 수다.
- FR-35-2 실행하면 아카이브마다 원본과 같은 위치에 풀고, 폴더 만들기는 #13 "스마트" 규칙을 아카이브별로 적용한다(최상위 항목이 하나면 그대로, 여러 개면 이름 폴더).
- FR-35-3 기존 동작(`*`를 아카이브 이름으로 바꾸는 `k_ReplaceAsterisk`)을 그대로 쓴다. 새 해제 경로를 만들지 않는다.
- FR-35-4 여러 아카이브는 S4 진행창 하나의 대기열(S4-07)로 처리한다.
- FR-35-5 분할 세트의 여러 조각을 함께 골랐으면 그 세트는 한 번만 푼다(#33 FR-33-8).
- FR-35-6 폴더와 아카이브가 섞여 있으면 지금처럼 S7-10을 숨긴다.

## 5. 동작 규칙과 예외

- 한 아카이브가 실패해도 나머지는 계속 푼다. 실패한 것은 마지막에 S9로 모아 보여 준다.
- 서로 다른 아카이브가 같은 결과 이름을 만들면(예: `a.zip`과 `a.7z` → `a\`) 두 번째 결과는 S2-09 "같은 파일 처리" 설정을 따른다. S7에서는 S8 저장값(기본 "매번 묻기")을 쓴다.
- #30 폴더 열기, #31 원본 휴지통, #32 완료 알림은 각 문서의 여러 아카이브 규칙을 따른다.
- 일반 파일과 아카이브가 섞여 있으면(폴더는 없음) 아카이브로 열리지 않는 파일에서 오류가 난다. 이 경우 해당 파일만 S9에 "아카이브가 아님"으로 표시한다.

## 8. 수용 기준

- [ ] `D:\dl`에서 `a.zip`(최상위 항목 3개), `b.zip`(최상위 폴더 `b-1.0\` 하나)을 고르고 우클릭하면 최상단에 "각각 폴더로 풀기 (2개)"가 있다.
- [ ] 실행하면 `D:\dl\a\`가 만들어지고, `b.zip`은 `D:\dl\b-1.0\`으로 풀린다(폴더가 한 겹 더 생기지 않음).
- [ ] 진행창(S4)이 하나만 뜨고 대기열에 두 번째 아카이브가 표시된다.
- [ ] `a.zip`과 폴더 `docs\`를 함께 고르면 S7-10 "각각 폴더로 풀기"가 나오지 않는다.
- [ ] `a.zip`, `bad.zip`(손상)을 함께 풀면 `a.zip`은 풀리고, 끝난 뒤 S9에 `bad.zip` 오류만 표시된다.
