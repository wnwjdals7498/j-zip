## 1. 목적

큰 파일을 메일에 첨부하거나 FAT32 USB에 옮기려면 정해진 크기로 나눠야 한다. 7-Zip은 이 기능이 있지만 프리셋이 `650M - CD`, `4480M - DVD` 같은 매체 기준이라 사용자가 숫자를 직접 계산해야 한다. j-zip은 같은 엔진을 쓰되 용도 이름으로 고르는 프리셋을 제공한다.

## 2. 현재 7-Zip 동작

- GUI: 압축 대화상자의 볼륨 콤보 `IDC_COMPRESS_VOLUME` (`CPP/7zip/UI/GUI/CompressDialogRes.h:10`). 콤보 항목은 `AddVolumeItems()`가 채움 (`CPP/7zip/UI/GUI/CompressDialog.cpp:495` → `CPP/7zip/UI/FileManager/SplitUtils.cpp:75`).
- 프리셋 목록 `k_Sizes[]` (`SplitUtils.cpp:61`): `10M`, `100M`, `1000M`, `650M - CD`, `700M - CD`, `4092M - FAT`, `4480M - DVD`, `8128M - DVD DL`, `23040M - BD`.
- 입력 해석 `ParseVolumeSizes()` (`SplitUtils.cpp:9`): 숫자 + 단위(`b`/`k`/`m`/`g`/`t`, 2진 단위 — `m` = 2^20). 공백으로 여러 크기를 줄 수 있고, `-`가 나오면 그 뒤는 무시함(그래서 `650M - CD`가 650M으로 읽힘). 0이나 숫자가 아닌 값은 실패.
- 확인 단계 (`CompressDialog.cpp:1216-1232`): 해석 실패 시 `IDS_INCORRECT_VOLUME_SIZE` 오류. 마지막 볼륨 크기가 100KB 미만이면 `IDS_SPLIT_CONFIRM`으로 한 번 더 물음.
- CLI: `-v` 스위치 (`CPP/7zip/UI/Common/ArchiveCommandLine.cpp:312`, `:990` `parser[NKey::kVolume]`).
- FM에는 기존 파일을 자르고 합치는 `IDM_SPLIT`/`IDM_COMBINE`도 있음 (`FileManager/PanelSplitFile.cpp`, `SplitDialog.cpp`). 이것은 아카이브 분할과 별개 기능임.
- 사용자에게 보이는 결과: `이름.7z.001`, `이름.7z.002` … 또는 ZIP이면 `이름.zip.001` … 형식의 조각 파일.

## 3. 요구사항

- FR-01-1 S3-07은 "나누지 않음 / 메일(25MB) / USB FAT32(4GB) / 직접 입력…" 네 항목을 이 순서로 보여준다. 기본값은 "나누지 않음".
- FR-01-2 "메일(25MB)"은 볼륨 크기 `25M`(25 × 2^20 바이트), "USB FAT32(4GB)"는 7-Zip 기존 값과 같은 `4092M`으로 압축 엔진에 넘긴다.
- FR-01-3 "직접 입력…"을 고르면 S3-07이 편집 가능한 입력으로 바뀌고, 입력값은 `ParseVolumeSizes()`와 같은 문법(숫자 + `K`/`M`/`G`, 공백 구분 여러 크기)을 받는다.
- FR-01-4 직접 입력 값이 잘못되면(빈 값, 0, 숫자 없음) S3-07 아래에 즉시 오류를 표시하고 S3-12 "압축"을 비활성화한다. 대화상자를 닫거나 메시지 상자를 띄우지 않는다.
- FR-01-5 볼륨 크기가 100KB 미만이면 7-Zip과 같이 실행 전에 확인을 받는다.
- FR-01-6 S8-03에서 사용자가 만든 프리셋(이름 + 크기)을 추가·삭제할 수 있고, 추가한 프리셋은 S3-07의 "직접 입력…" 바로 위에 나타난다.
- FR-01-7 "나누지 않음" 이외를 고르면 결과 조각 이름 규칙을 S3-07 아래 보조 텍스트로 보여준다(예: "자료.zip.001, 자료.zip.002 … 로 저장").
- FR-01-8 S3-04에서 EXE를 고르면 S3-07은 "나누지 않음"으로 고정되고 비활성 + 이유 툴팁을 표시한다(F06 참조).
- FR-01-9 분할 결과는 7-Zip 26.04로 만든 분할 아카이브와 같은 형식이어야 한다(조각 파일을 7-Zip으로 열 수 있음).

## 5. 동작 규칙과 예외

- 단위는 7-Zip과 같이 2진 단위로 해석한다. "25MB"라는 표시는 편의 표기이며 실제 값은 25 × 2^20 바이트다.
- 볼륨 크기가 결과 아카이브보다 크면 조각 1개(`.001`)만 생긴다. 이것은 7-Zip과 같은 동작이며 오류가 아니다.
- 저장 위치에 이미 같은 이름의 조각(`.001` 등)이 있으면 S3-12 실행 시 덮어쓸지 확인한다.
- 분할 + 암호(#4), 분할 + 4GB 초과(#2)는 함께 쓸 수 있다.
- 분할된 아카이브를 여는 동작은 #33(F33)에서 다룬다.

## 9. 범위 밖·미결 사항
