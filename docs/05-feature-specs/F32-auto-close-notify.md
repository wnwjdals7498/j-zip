## 1. 목적

지금 7-Zip 진행창은 성공하면 말없이 사라져서, 큰 작업을 맡기고 다른 일을 하던 사용자는 끝났는지 알기 어렵다. 반대로 결과 수치를 보고 싶은 사용자는 창이 닫혀 버려 볼 수 없다. "끝나면 이 창 닫기"를 사용자가 고르게 하고, 창이 보이지 않는 상태로 끝난 작업은 Windows 알림으로 결과와 다음 동작을 알려 준다.

## 2. 현재 7-Zip 동작

- `CPP/7zip/UI/FileManager/ProgressDialog2.cpp:991-1047` `CProgressDialog::OnExternalCloseMessage`: 메시지가 없으면 무조건 `End(0)`로 닫는다. 메시지가 있으면 `_waitCloseByCancelButton`으로 사용자가 닫을 때까지 기다린다. 작업 표시줄 진행률은 `SetTaskbarProgressState` (research #32).
- "완료 후 닫기" 체크박스 없음(`ProgressDialog2Res.h`에 해당 ID 없음). 토스트, `FlashWindow`, `Shell_NotifyIcon` 검색 결과 0건 (research #32).
- 백그라운드 버튼 `IDB_PROGRESS_BACKGROUND`, 일시정지 `IDB_PAUSE`가 있다 (research #32).
- 사용자 입장: 성공하면 진행창이 바로 사라지고 아무 알림도 없다. 오류가 있으면 창이 남아 메시지 목록을 보여 준다.

## 3. 요구사항

- FR-32-1 S4에 "끝나면 이 창 닫기"(S4-06)를 둔다. 기본값은 S8-02 값이며, 처음 설치 시 켜짐이다. 진행 중에 바꿀 수 있다.
- FR-32-2 작업이 오류·경고 없이 끝나면: S4-06이 켜져 있으면 진행창을 닫고, 꺼져 있으면 진행창을 "완료" 상태(S4-12: 진행 막대 100%, 버튼 "닫기")로 남긴다.
- FR-32-3 오류·경고가 있으면 S4-06 값과 관계없이 진행창을 닫지 않고 S9를 표시한다(현재 7-Zip의 메시지 대기 동작 유지).
- FR-32-4 완료 알림(S4-10)은 작업이 끝날 때 진행창이 사용자에게 보이지 않던 경우에 띄운다: (a) S4-08 "백그라운드로"로 숨긴 경우, (b) S4-06으로 자동으로 닫힌 경우, (c) 진행창이 최소화돼 있던 경우.
- FR-32-5 진행창이 화면에 보이고 S4-06이 꺼져 있어 창이 남는 경우에는 알림을 띄우지 않는다.
- FR-32-6 S4-10 내용: 제목 = "{동작} 완료"(예: "압축 풀기 완료"), 요약 = "{이름} · 파일 N개 · 크기 · 걸린 시간", 버튼 최대 2개(C21). 해제 작업은 [폴더 열기](F30-open-folder-after.md)와 [압축 파일 휴지통으로](F31-recycle-after.md). 압축·테스트 작업의 버튼은 5절 참고.
- FR-32-7 오류로 끝난 작업이 숨겨져 있었으면(S4-08) 성공 알림 대신 "{동작} 중 문제 발생 · 파일 N개" 알림을 띄우고, 누르면 S9를 연다.
- FR-32-8 알림은 Windows 앱 알림 설정(방해 금지 등)을 따른다. Windows가 알림을 막아 두었으면 작업 표시줄 단추를 깜박여 완료를 알린다.
- FR-32-11 S4-10은 패키지 앱(MSIX)의 `Microsoft.Windows.AppNotifications.AppNotificationManager`로 띄운다([07. 기술 스택](../07-tech-stack.md) 7절).
- FR-32-12 `JZip.exe`가 관리자 권한(elevated)으로 실행 중이면 앱 알림이 조용히 실패하므로 알림을 띄우지 않는다. 대신 S4-06 값과 관계없이 진행창을 닫지 않고 S4-12 완료 상태로 남기며, 숨겨져 있었으면(S4-08) 다시 보이게 하고 작업 표시줄 단추를 깜박인다.
- FR-32-9 S4-08 "백그라운드로"를 누르면 진행창을 숨기고 작업 우선순위를 낮춘다. 작업 표시줄 진행률은 계속 표시한다.
- FR-32-10 여러 작업이 대기열(S4-07)에 있으면 마지막 작업이 끝났을 때 한 번만 알린다. 요약은 "N개 작업 완료"로 합친다.

## 5. 동작 규칙과 예외

- 압축(S3) 완료 알림 버튼: [폴더 열기] 버튼(만든 아카이브를 선택한 상태로 탐색기 열기) 1개. 테스트(S1-06, S7-06) 완료 알림: 버튼 없이 "이상 없음 · 파일 N개".
- 취소한 작업은 알림을 띄우지 않는다.
- S4-06이 꺼져 있어 "완료" 상태로 남은 창에서 `Esc`/`Enter`는 창을 닫는다.
- S1 메인 창에서 실행한 짧은 작업(1초 미만)도 같은 규칙을 따른다. 1초 미만 작업에 알림을 띄울지는 9절 미결.
- 현재 7-Zip은 오류가 없어도 `fm.OkMessage`가 있으면 메시지 상자를 띄운다(`OnExternalCloseMessage` 안). 이 메시지 상자와 S4-10이 겹쳐 뜨지 않게 한다.
- 알림 버튼 동작(#30, #31)은 각 문서의 규칙을 따른다. 알림을 늦게 눌러 대상이 사라졌으면 안내만 한다.

## 7. 구현 지점

- `CPP/7zip/UI/FileManager/ProgressDialog2.cpp` `CProgressDialog::OnExternalCloseMessage`(991행): 무조건 `End(0)` 하는 분기를 S4-06 값으로 나누고, 알림 호출을 추가한다 (research #32).
- `ProgressDialog2.cpp` `ProcessWasFinished`(1305행) (research #32).
- `ProgressDialog2Res.h`: S4-06 체크박스 ID 새로 추가 (research #32).
- 백그라운드: 기존 `IDB_PROGRESS_BACKGROUND` 처리를 창 숨김까지 확장 (research #32).
- 진행창 S4는 `JZip.exe`(WinUI 3) 비모달 창으로 새로 만든다. 위 7-Zip 파일은 닫기·백그라운드 동작의 근거이며, 완료·오류 판정 로직은 `jzip-core`로 옮긴다.
- 알림(S4-10): `JZip.exe`에서 `AppNotificationManager::Default().Register()`를 활성화 처리(`GetActivatedEventArgs()`) 이전에 호출하고, `AppNotificationBuilder`로 제목·요약·버튼을 만든다. 버튼·본문 클릭은 알림 활성화 인자로 받아 #30·#31 동작 또는 S9를 연다.
- 매니페스트: `windows.toastNotificationActivation` + `windows.comServer`(알림 활성화용)를 MSIX 매니페스트에 선언한다(#27).
- 관리자 권한 판별(FR-32-12): 프로세스 토큰의 권한 상승 여부로 판단한다(시제품 SP-4에서 확인).

## 8. 수용 기준

- [ ] S4-06 켜짐으로 1 GB ZIP을 풀면 끝나자마자 진행창이 닫히고 "압축 풀기 완료" 알림이 뜬다.
- [ ] S4-06 꺼짐으로 풀면 진행창이 100% "완료" 상태로 남고 알림은 뜨지 않는다.
- [ ] 진행 중 S4-08 "백그라운드로"를 누르면 창이 사라지고, 끝나면 알림이 뜬다. 알림의 [폴더 열기]가 결과 폴더를 연다.
- [ ] CRC 오류가 있는 ZIP을 S4-06 켜짐으로 풀면 진행창이 닫히지 않고 S9가 표시된다.
- [ ] 같은 손상 ZIP을 백그라운드로 풀면 "압축 풀기 중 문제 발생" 알림이 뜨고, 누르면 S9가 열린다.
- [ ] Windows "방해 금지"를 켠 상태에서 백그라운드 작업이 끝나면 작업 표시줄 단추가 깜박인다.
- [ ] 3개 파일을 대기열로 풀면 알림이 1번만 뜨고 "3개 작업 완료"로 표시된다.
- [ ] 해제 중 취소하면 알림이 뜨지 않는다.
- [ ] `JZip.exe`를 관리자 권한으로 실행해 S4-06 켜짐으로 풀면 알림이 뜨지 않고 진행창이 S4-12 완료 상태로 남는다.
- [ ] S8-02에서 "끝나면 이 창 닫기"를 끄면 다음 진행창의 S4-06 기본값이 꺼짐이다.

## 9. 범위 밖·미결 사항

- 범위 밖: 완료 소리, 시스템 트레이 아이콘 상주, 작업 완료 후 PC 종료.
- 해결: j-zip은 MSIX로만 배포하므로(#27) 패키지 ID로 앱 알림을 띄운다. MSI·포터블용 AppUserModelID 등록은 필요 없다.
- 선행 검증(SP-4, 07 문서 9절): 관리자 권한 실행 시 앱 알림이 조용히 실패하는 문제와 FR-32-12 대체 동작을 시제품으로 확인한다.
- 미결: 1초 미만 작업에도 알림을 띄울지(짧은 작업이 많으면 알림이 쌓임).
- 미결: 기존 7-Zip 백그라운드 버튼이 창을 숨기는지, 우선순위만 바꾸는지는 research 자료에서 확인하지 않았다(버튼 ID만 확인).
- 해결: S4-06 문구는 "끝나면 이 창 닫기"로 통일했다(06).
- 미결: 06 문서는 `Progress.CloseWhenDone`을 S8-02 "압축 풀기" 탭에만 두는데, 압축·테스트 진행창에도 같은 값을 쓸지 별도 값을 둘지.
- 06에 반영됨 (S8-19, S4-12). Progress 디자인의 완료 상태 화면은 디자인 쪽에서 추가한다.
