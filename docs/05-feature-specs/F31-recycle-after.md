## 1. 목적

내려받은 압축 파일을 풀고 나면 원본은 대개 필요 없지만, 사용자가 직접 찾아 지워야 한다. 해제가 문제없이 끝났을 때만 원본 아카이브(분할이면 모든 조각)를 **휴지통으로** 보내, 실수해도 되돌릴 수 있게 정리한다.

## 2. 현재 7-Zip 동작

- 해제 경로에서 원본을 지우는 코드 없음: `Extract.cpp`, `ExtractGUI.cpp`, `CompressCall2.cpp`에서 `DeleteFileAlways`/`FO_DELETE` 0건 (research #31).
- 압축 후 원본 삭제는 있다: `-sdel` (`ArchiveCommandLine.cpp:361`, `:1813`), GUI `IDX_COMPRESS_DEL 4019` (`CompressDialog.cpp:543,1175`). 구현은 `UI/Common/Update.cpp:1853~` `DeleteFileAlways`이며 **휴지통이 아닌 영구 삭제**다 (research #31).
- 사용자 입장: 해제 후 원본 아카이브는 그대로 남는다.

## 3. 요구사항

- FR-31-1 S2에 "끝나면 압축 파일을 휴지통으로"(S2-07)를 둔다. 기본값은 S8-02 값이며, 처음 설치 시 꺼짐이다.
- FR-31-2 원본은 반드시 **휴지통**으로 보낸다. 영구 삭제(`-sdel`의 `DeleteFileAlways` 방식)는 어떤 경우에도 쓰지 않는다.
- FR-31-3 다음 조건을 모두 만족할 때만 실행한다: 작업이 취소되지 않음, 오류 0개, 경고 0개, 아카이브 전체를 풀었음(S1-19처럼 일부 항목만 푼 경우 제외).
- FR-31-4 분할 아카이브(#33)는 그 해제에 쓰인 모든 조각(`.z01`…`.zip`, `.001`…, `.partN.rar` 등)을 함께 휴지통으로 보낸다. 일부 조각만 보내지 않는다.
- FR-31-5 여러 아카이브를 한 번에 풀면(#35) 아카이브마다 따로 판단한다. 성공한 아카이브만 휴지통으로 보낸다.
- FR-31-6 휴지통을 쓸 수 없는 위치(네트워크 공유, 휴지통이 꺼진 드라이브 등)에서는 지우지 않고, 완료 결과에 "휴지통을 쓸 수 없는 위치라서 원본을 남겨 둠"을 표시한다.
- FR-31-7 휴지통 이동에 실패하면(다른 프로그램이 파일을 사용 중 등) 원본을 남기고 결과에 이유를 표시한다. 해제 결과 자체는 성공으로 둔다.
- FR-31-8 S4-10 완료 알림의 "압축 파일 휴지통으로" 버튼은 S2-07이 꺼져 있을 때도 FR-31-3~FR-31-7 규칙으로 실행한다. S2-07로 이미 보냈으면 이 버튼은 표시하지 않는다.
- FR-31-9 S7-01, S7-02, S7-10처럼 S2 없이 시작한 해제는 S8-02 저장값을 쓴다.
- FR-31-10 CLI(7z.exe)에 같은 동작을 하는 새 스위치를 추가한다. 휴지통을 쓸 수 없으면 원본을 남긴다.

## 5. 동작 규칙과 예외

- 오류·경고가 있으면 S9가 뜨고 원본은 남는다(06 문서 S2-07 "오류가 있으면 실행하지 않음").
- `.tar.gz` 한 번에 풀기(#12)에서는 사용자가 연 바깥 파일(`.tar.gz`)을 보낸다. 중간 `.tar`는 임시 결과이므로 대상이 아니다.
- 7zFM(S1)에서 지금 열려 있는 아카이브를 풀면, 휴지통으로 보내기 전에 S1의 해당 탭(또는 패널)을 닫아 파일 잠금을 푼다. 다른 프로세스가 잡고 있으면 FR-31-7.
- 풀 위치가 원본 아카이브와 같은 파일 이름을 덮어쓰는 경우(드묾)는 원본을 이미 덮어쓴 것이므로 휴지통 처리를 하지 않는다.
- #30 폴더 열기와 함께 켜져 있으면, 휴지통 이동을 먼저 하고 폴더를 연다(탐색기에 원본이 남아 보이지 않도록).
- 휴지통 이동은 사용자 확인 대화상자를 띄우지 않는다(옵션을 켠 것이 곧 확인).

## 9. 범위 밖·미결 사항

- 범위 밖: 압축 후 원본 삭제(S3-10, `-sdel`)를 휴지통 방식으로 바꾸는 것. 필요하면 별도 기능으로 다룬다.
- 미결: CLI 새 스위치의 이름. research 자료는 추가 위치만 적었다.
- 미결: 휴지통 사용 가능 여부를 미리 판별하는 방법. `FOF_ALLOWUNDO`는 휴지통을 쓸 수 없는 위치에서 영구 삭제로 바뀌거나 확인을 물을 수 있어서, 호출 전에 판별하거나 `IFileOperation` 등 다른 API를 써야 할 수 있다. research 자료에서는 확인하지 않았다.
- 해결: 화면은 "S2 S4 S8"로 통일했다(03, 05 README). FeatureMap 디자인의 "S2 S8" 표기는 디자인 쪽에서 고친다.
- 해결: S2-07 문구는 "끝나면 압축 파일을 휴지통으로"로 통일했다(06).
- 06에 반영됨 (S4-11). 오류·경고가 있으면 원본을 처리하지 않으므로 S9에는 따로 두지 않는다.
