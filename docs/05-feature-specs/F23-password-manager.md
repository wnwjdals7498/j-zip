## 1. 목적

회사 공유 자료나 반복해서 받는 암호 아카이브를 풀 때마다 암호를 찾아 입력하는 수고를 줄인다.
j-zip은 암호를 Windows 계정에 묶인 DPAPI로 암호화해 저장하고, 풀 때 저장된 암호를 먼저 자동으로 넣어 본다. 맞는 암호가 없을 때만 S6 입력 창을 띄운다.

## 2. 현재 7-Zip 동작

- 저장: `CPP/7zip/UI/Common/ZipRegistry.cpp`는 `ShowPassword` 플래그(95행)만 저장한다. 비밀번호 저장, `CryptProtectData`, DPAPI 관련 코드는 검색 결과 0건.
- 입력 UI: `CPP/7zip/UI/FileManager/PasswordDialog.cpp`, 해제 대화상자 `CPP/7zip/UI/GUI/ExtractDialog.cpp`(`IDE_EXTRACT_PASSWORD` 120). 압축 대화상자 암호 입력은 `IDE_COMPRESS_PASSWORD1`(120), 방식 콤보 `IDC_COMPRESS_ENCRYPTION_METHOD`(122).
- 해제 중 암호 요청: `CPP/7zip/UI/FileManager/ExtractCallback.cpp`.
- 사용자 입장: 암호 아카이브를 열 때마다 직접 입력해야 한다.

## 3. 요구사항

### 저장과 보안

- FR-23-1 저장하는 암호는 항목마다 Windows DPAPI(`CryptProtectData`, 현재 사용자 범위, 로컬 컴퓨터 범위 플래그 사용 안 함)로 암호화한다. 평문 암호를 디스크, 레지스트리, 로그, 크래시 덤프용 파일에 쓰지 않는다.
- FR-23-2 DPAPI 호출에는 j-zip 고유의 추가 엔트로피 값을 넘겨, 같은 사용자의 다른 프로그램이 같은 blob을 그대로 복호화하기 어렵게 한다.
- FR-23-3 저장 위치는 사용자 프로필의 j-zip 데이터 폴더 아래 파일 하나다. 항목 형식: 이름(평문), 암호 blob(DPAPI), 마지막 사용 시각(평문), 만든 시각(평문).
- FR-23-4 복호화한 암호는 사용 직후 메모리에서 지운다(버퍼 덮어쓰기). 목록 화면(S6-07)에는 복호화하지 않고 고정 길이 마스크 `••••••`만 표시한다(암호 길이를 드러내지 않음).
- FR-23-5 S6-07 "편집"에서 암호를 보려면 보기 토글(C04)을 누른 때만 복호화한다. S6-10이 켜져 있으면 그 전에 Windows Hello 확인을 거친다.
- FR-23-6 S6-10 "관리자를 열 때 Windows Hello로 확인"이 켜져 있으면 S6 관리자 창을 열 때 Windows Hello(또는 Windows 계정 PIN/암호) 확인을 요구한다. 확인은 WinRT `Windows.Security.Credentials.UI.UserConsentVerifier`(`RequestVerificationAsync`)로 하며, 결과가 `Verified`가 아니면 창을 열지 않는다. `CheckAvailabilityAsync`가 사용 불가를 돌려주면 S6-10을 비활성으로 두고 이유를 표시한다.
- FR-23-7 S6-11 문구: "암호는 이 PC의 Windows 계정으로 암호화해서 저장함 (다른 PC로 복사해도 열리지 않음)".
- FR-23-8 저장 파일을 복호화하지 못하면(다른 PC·다른 계정에서 복사함, 손상) 해당 항목은 "이 PC에서 열 수 없음"으로 표시하고 자동 시도에서 제외한다. 사용자가 삭제할 수 있다.

### 자동 시도

- FR-23-9 S6-09 "압축 풀 때 저장된 암호를 먼저 자동으로 넣어 보기"가 켜져 있으면, 해제·테스트·목록 보기 중 암호가 필요할 때 저장된 암호를 마지막 사용 시각이 최근인 순서로 넣어 본다.
- FR-23-10 자동 시도는 "맞음"을 확인할 수 있을 때만 성공으로 본다: 7z 헤더 암호화는 헤더 복호화·CRC 성공, AES(ZIP)는 암호 검증값 일치 후 첫 파일 CRC/인증 성공, ZipCrypto는 검증 바이트 일치 후 그 파일의 CRC 성공. ZipCrypto 검증 바이트만 맞고 CRC가 틀리면 다음 암호로 넘어간다.
- FR-23-11 자동 시도가 성공하면 S6을 띄우지 않고 그 암호로 계속하며 그 항목의 마지막 사용 시각을 갱신한다.
- FR-23-12 자동 시도가 모두 실패하면 S6 입력 창을 띄우고 S6-02에 "저장된 암호 N개를 먼저 넣어 봤지만 맞지 않음"을 표시한다.
- FR-23-13 자동 시도는 아카이브 하나당 최대 20개 항목 또는 10초 중 먼저 닿는 쪽까지만 한다(7z AES 키 유도 비용 때문). 남은 항목이 있으면 S6-02 문구에 "(최근 20개만 시도)"를 붙인다.

### 입력과 저장

- FR-23-14 S6-04 "이 암호를 관리자에 저장"을 켜고 확인하면, 그 암호로 FR-23-10 기준의 첫 성공이 확인된 뒤에만 저장한다. 틀린 암호는 저장하지 않는다.
- FR-23-15 이미 같은 암호가 저장돼 있으면 새 항목을 만들지 않고 마지막 사용 시각만 갱신한다(비교는 복호화한 값으로 메모리에서만).
- FR-23-16 새 항목의 기본 이름은 아카이브 파일 이름이다. S6-07 "편집"에서 바꿀 수 있다.
- FR-23-17 S6-08 "+ 추가"는 이름과 암호를 입력받아 저장한다. 빈 암호는 저장하지 않는다.
- FR-23-18 S3-08 "저장된 암호 ▾"는 저장된 항목 이름 목록을 보여 주고, 고르면 암호 입력란에 값을 채운다(가려진 상태). S6-10이 켜져 있으면 목록을 열 때 Windows Hello 확인을 거친다.

### 메모리

- FR-23-19 평문 암호를 담았던 버퍼(입력란에서 받은 값, 복호화한 값, 자동 시도용 사본)는 사용이 끝나면 `SecureZeroMemory`로 지운다(컴파일러 최적화로 제거되지 않는 방식). 크래시 덤프에 평문 암호가 남는 시간을 줄이기 위해서다([10](../10-logging-evidence-operations.md) 7절 덤프 안내).

## 5. 동작 규칙과 예외

- 보안 전제와 한계(사용자 안내 문서에 명시):
  - DPAPI 사용자 범위 암호화는 다른 Windows 계정과, 파일을 다른 PC로 복사한 공격자로부터 보호한다.
  - 같은 사용자 권한으로 실행 중인 악성 프로그램은 DPAPI로 복호화할 수 있으므로 이를 막지 못한다. Windows Hello 확인(S6-10)은 j-zip 화면 접근을 막는 UI 차원의 확인이며 저장 암호화 강도를 높이지 않는다.
  - Windows 계정 암호를 관리자 권한으로 강제 재설정하면 DPAPI 마스터 키 접근을 잃어 저장 암호를 복호화하지 못할 수 있다(FR-23-8로 처리).
- 자동 시도는 저장된 암호를 외부로 보내지 않는다. 다만 악의적으로 만든 아카이브가 어떤 저장 암호로 열리는지(성공 여부)는 사용자가 볼 수 있는 결과로 드러나므로, 자동 시도를 원하지 않는 사용자는 S6-09를 끌 수 있다.
- 저장 파일은 MSIX 앱 데이터 경로(사용자별) `LocalState\passwords.json`에 두며, j-zip을 제거하면 함께 지워진다(#27). 경로는 `JZip.exe`가 구해 `jzip-core`에 주입한다.
- 암호 입력란 내용은 클립보드 복사를 막지 않는다(사용자 선택). 보기 토글 상태는 기존 `ShowPassword` 플래그를 따른다.
- 저장 파일 쓰기·읽기는 설정 파일과 같은 규칙을 따른다([08. 아키텍처](../08-architecture.md) 6절): 명명된 뮤텍스 `Local\JZip.Passwords`를 잡고, 파일을 다시 읽어 병합한 뒤, 고유 임시 파일에 써서 `ReplaceFileW`(대상이 없으면 `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`)로 교체하고 실패하면 재시도한다. 읽기에 실패하면 마지막으로 읽은 값을 유지한다.
- 관리자 창(S6)은 비모달 창이다(06 문서 1절). 동시에 두 개를 열지 않는다.

## 7. 구현 지점

- `JZip.exe`(WinUI 3) 화면: S6 암호 입력 대화상자(S6-01~S6-06), 관리자 창(S6-07~S6-11), D2, S3-08 "저장된 암호 ▾". 기존 파일 `CPP/7zip/UI/FileManager/PasswordDialog.cpp`, `CPP/7zip/UI/GUI/ExtractDialog.cpp`(`IDE_EXTRACT_PASSWORD` 120), `CPP/7zip/UI/GUI/CompressDialog.cpp`(`IDE_COMPRESS_PASSWORD1` 120)는 현재 동작 근거로만 쓴다.
- `JZip.exe`: Windows Hello 확인은 `UserConsentVerifier`(C++/WinRT, `co_await`)로 호출한다(07 문서 7절). `jzip-core`에는 `IUserConsent` 포트만 두고 `JZip.exe`가 이 구현을 주입한다(코어는 WinRT를 참조하지 않음, [08](../08-architecture.md) 1절).
- `jzip-core` 로직: 암호 요청 지점(기존 파일 `CPP/7zip/UI/FileManager/ExtractCallback.cpp`)에서 자동 시도를 먼저 수행하고, 실패 시에만 S6 화면을 요청한다.
- `jzip-core` 저장소: 새 파일로 둔다. 기존 설정 저장(`CPP/7zip/UI/Common/ZipRegistry.cpp`, 현재 95행 `ShowPassword`만 있음)은 참고만 한다. DPAPI(`CryptProtectData`) 호출과 파일 입출력은 이 저장소 모듈(`ISecretStore` 구현) 안에만 둔다.

## 8. 수용 기준

- [ ] 암호 `abc123!`로 만든 `p.7z`(헤더 암호화)를 풀 때 S6-04를 켜고 맞는 암호를 넣으면 관리자 목록에 "p.7z" 항목이 생긴다.
- [ ] 틀린 암호 `wrong`을 넣고 S6-04를 켠 채 확인하면 항목이 생기지 않는다.
- [ ] 같은 암호로 만든 `q.zip`(AES-256)을 풀면 S6이 뜨지 않고 풀리며, "p.7z" 항목의 마지막 사용이 갱신된다.
- [ ] 저장된 항목이 3개이고 모두 틀린 `r.zip`을 풀면 S6-02에 "저장된 암호 3개를 먼저 넣어 봤지만 맞지 않음"이 보인다.
- [ ] ZipCrypto `z.zip`에서 검증 바이트만 우연히 맞는 틀린 암호가 저장돼 있어도 결과 파일 CRC 오류 없이 올바른 암호로 넘어가거나 S6이 뜬다.
- [ ] 저장 파일을 텍스트·16진수 편집기로 열어 `abc123!` 문자열(ASCII, UTF-16 모두)이 없다.
- [ ] 저장 파일을 다른 Windows 계정 프로필로 복사해 j-zip을 실행하면 항목이 "이 PC에서 열 수 없음"으로 표시되고 자동 시도에 쓰이지 않는다.
- [ ] S6-07 목록의 마스크 길이가 암호 길이와 관계없이 같다.
- [ ] S6-10을 켜면 관리자 창을 열 때 Windows Hello 확인이 뜨고, 취소하면 창이 열리지 않는다.
- [ ] S6-09를 끄면 `q.zip`을 풀 때 S6이 뜨고 S6-02 배너는 보이지 않는다.
- [ ] S3에서 S3-08 "저장된 암호 ▾"로 항목을 고르면 암호란이 가려진 값으로 채워지고, 만든 아카이브가 그 암호로 풀린다.

## 9. 범위 밖·미결 사항
