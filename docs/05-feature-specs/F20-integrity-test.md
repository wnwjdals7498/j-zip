## 1. 목적

받은 아카이브나 백업이 깨지지 않았는지 풀지 않고 확인한다. 7-Zip에 이미 있으나 결과가 텍스트 메시지 목록이라 어느 파일이 왜 깨졌는지, 다음에 무엇을 할지 알기 어렵다.
j-zip은 같은 테스트 엔진을 쓰고, 결과를 S9에서 요약·목록·후속 동작으로 보여 준다.

## 2. 현재 7-Zip 동작

- 우클릭 명령 `kTest`: `CPP/7zip/UI/Explorer/ContextMenuFlags.h`, `ContextMenu.cpp:277`.
- 실행: `CPP/7zip/UI/Common/CompressCall.cpp:278` `TestArchives` → 7zG 테스트.
- CLI `t` 명령.
- 결과 표시: 진행창 결과와 메시지 목록(`CPP/7zip/UI/FileManager/MessagesDialog.cpp`, 06 문서 1절 대응표).
- 사용자 입장: 오류가 없으면 진행창이 닫히고 끝난다(#32). 오류가 있으면 메시지 목록에 파일별 오류 문장이 나온다.

## 3. 요구사항

- FR-20-1 S1-06 "테스트"와 S7-06 "압축 파일 테스트"는 기존 테스트 엔진으로 아카이브 전체를 검사하고 S4에 진행 상황을 표시한다(S4-01 "테스트 중 — {이름}").
- FR-20-2 오류가 없으면 S4 완료 알림(S4-10 형식)에 "문제 없음 · 파일 N개 확인"을 표시하고 S9는 띄우지 않는다.
- FR-20-3 오류가 하나라도 있으면 S9를 띄운다. S9-01 = "파일 N개가 손상됨 · 정상 M개", S9-02 = 손상 파일 경로와 오류 종류.
- FR-20-4 오류 종류는 엔진 결과를 다음 네 가지로 묶어 표시한다: "CRC 오류", "데이터 끝남"(예기치 않은 끝), "헤더 오류"(헤더·데이터 오류), "암호 틀림". 그 밖의 결과는 "기타 오류"로 표시하고 원문을 "자세히"에 둔다.
- FR-20-5 S9-04 "정상 파일 M개만 풀기"는 손상 항목을 제외한 선택으로 S2를 연다.
- FR-20-6 S9-05 "복구 시도…"는 ZIP일 때만 활성이다(#24). 다른 형식에서는 비활성 + 툴팁 "ZIP만 복구할 수 있음".
- FR-20-7 S9-06 "결과 복사"는 아카이브 경로, 요약, 손상 목록(경로 + 오류 종류)을 한 줄씩 텍스트로 클립보드에 넣는다.
- FR-20-8 여러 아카이브를 테스트하면 아카이브별 결과를 S9-02에 묶어 표시한다(아카이브 이름이 그룹 머리).

## 5. 동작 규칙과 예외

- 암호 아카이브: 테스트에도 암호가 필요하다. S6 흐름(#23 자동 시도 포함)을 따른다. 암호를 건너뛴 파일은 "암호 틀림"이 아니라 "건너뜀"으로 표시하고 손상 개수에 넣지 않는다.
- 아카이브 자체를 열 수 없으면(형식 인식 실패) S9 대신 오류 메시지 "압축 파일을 열 수 없음 · 손상됐거나 지원하지 않는 형식"을 띄운다. ZIP이면 S9-05를 함께 제공한다.
- 분할 아카이브의 조각이 빠졌으면 S9 분할 안내(#33)를 먼저 보인다.
- 악성코드 검사(#21)를 켰으면 S9-03에 결과를 함께 보인다.
