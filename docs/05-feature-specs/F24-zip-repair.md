## 1. 목적

다운로드가 중간에 끊기거나 저장 장치 오류로 ZIP 끝부분(중앙 디렉터리)이 깨지면 일반 프로그램은 아예 열지 못한다.
7-Zip은 이미 로컬 헤더를 훑어 남은 파일을 읽어 낼 수 있지만, 그 결과를 다른 프로그램에서도 열리는 정상 ZIP으로 저장하지는 못한다.
j-zip은 읽어 낸 항목들의 압축 데이터를 다시 압축하지 않고 그대로 복사하고 새 중앙 디렉터리를 써서 "복구 사본"을 만든다. 원본은 바꾸지 않는다.

## 2. 현재 7-Zip 동작

- 폴백 읽기: `CPP/7zip/Archive/Zip/ZipIn.cpp:63-65`, `:2544` 주석 "LOCALS-CD-MODE : slow mode, if CD-MODE fails : we sequentially read all Locals". `:2076` `CInArchive::ReadLocals`, `:2794`에서 호출.
- 강제 모드: `-mros` → `ZipHandlerOut.cpp:579-581` `"ros"` → `_force_OpenSeq` → `ZipHandler.cpp:775` `Force_ReadLocals_Mode`.
- "repair"·"recover" 명령은 없다.
- 사용자 입장: CD가 깨진 ZIP도 7-Zip으로 열어 풀 수 있는 경우가 많다. 그러나 결과를 다른 사람에게 보내거나 다른 프로그램으로 열려면 전부 풀어서 다시 압축해야 한다.

## 3. 요구사항

- FR-24-1 S9-05 "복구 시도…"는 ZIP 형식(확장자 `.zip` 또는 ZIP 핸들러로 열린 파일)일 때만 활성이다.
- FR-24-2 누르면 저장 위치 대화상자를 연다. 기본 파일 이름은 `{원본 이름} (복구).zip`, 기본 폴더는 원본과 같은 폴더다. 같은 이름이 있으면 `(복구 2)`, `(복구 3)` …으로 비어 있는 이름을 제안한다.
- FR-24-3 원본 파일은 읽기만 하고 절대 쓰지 않는다. 저장 위치로 원본 경로 자체를 고르면 거부하고 "원본과 다른 이름으로 저장해야 함"을 표시한다.
- FR-24-4 복구는 로컬 헤더 순차 읽기(`ReadLocals`) 결과를 기준으로 한다. 원본의 CD가 정상이어도 CD와 로컬 헤더를 대조해 둘 다에 있는 항목을 쓴다.
- FR-24-5 각 항목의 압축 데이터는 다시 압축하지 않고 바이트 그대로 복사한다. 암호화된 항목도 그대로 복사하므로 복구에 암호가 필요 없다.
- FR-24-6 데이터가 파일 끝에서 잘려 끝까지 읽을 수 없는 항목은 사본에 넣지 않는다.
- FR-24-7 "CRC가 맞지 않는 항목도 넣기" 옵션(기본 꺼짐)이 꺼져 있으면 복사 중 CRC 확인에 실패한 항목을 제외한다. 암호화 항목은 CRC를 확인할 수 없으므로 데이터 길이가 온전하면 넣는다.
- FR-24-8 새 CD와 끝 레코드를 쓰고, 항목 수·크기에 따라 Zip64 레코드를 쓴다(기존 `ZipOut.cpp` 규칙).
- FR-24-9 복구가 끝나면 사본을 테스트(#20 엔진)하고 S4-10 형식으로 "복구 완료 · 항목 N개 저장, M개 제외"와 [폴더 열기] [사본 열기]를 보인다.
- FR-24-10 제외된 항목이 있으면 S9를 다시 그려 S9-02에 제외 항목과 이유("데이터 잘림", "CRC 오류", "헤더 오류")를 보이고, S9-06 "결과 복사"로 복사할 수 있게 한다.
- FR-24-11 살릴 항목이 0개이면 사본을 만들지 않고 "복구할 수 있는 파일을 찾지 못함"을 표시한다.
- FR-24-12 분할 ZIP(`.z01`…)은 이번 범위에서 제외한다. 분할 ZIP에서 S9-05는 비활성 + 툴팁 "분할 압축 파일은 복구할 수 없음".

## 5. 동작 규칙과 예외

- 취소하거나 쓰기에 실패하면 만들던 사본 파일을 지운다. 원본은 항상 그대로다.
- 디스크 여유 공간이 원본 크기보다 작으면 시작 전에 경고한다.
- 로컬 헤더에 크기 정보가 없는 항목(데이터 디스크립터 사용)은 기존 `ReadLocals`가 찾은 끝 위치를 따른다. 끝을 정할 수 없으면 "헤더 오류"로 제외한다.
- 원본 파일명 인코딩(#17)은 바꾸지 않는다. 이름 바이트와 UTF-8 플래그를 그대로 복사한다.
- 원본의 아카이브 주석(#16)은 CD 끝 레코드에서 읽을 수 있으면 복사하고, 읽을 수 없으면 빼고 결과 요약에 "주석은 복구하지 못함"을 표시한다.
- 테스트 결과(#20) 화면 외에, 아카이브 자체를 열지 못한 오류 메시지에서도 ZIP이면 같은 복구 동작을 제공한다(#20 5절).

## 8. 수용 기준

- [ ] 파일 20개짜리 정상 `a.zip`의 끝 100바이트(CD 일부)를 잘라 `a_cut.zip`을 만들고, S9-05로 복구하면 `a_cut (복구).zip`이 생기고 `7z t`가 오류 없이 끝나며 항목이 20개다.
- [ ] 위 사본을 Windows 탐색기 기본 ZIP 기능으로 열 수 있다.
- [ ] `a.zip`의 마지막 파일 데이터 중간에서 잘라 낸 `b_cut.zip`을 복구하면 사본에 19개가 있고 S9-02에 마지막 파일이 "데이터 잘림"으로 보인다.
- [ ] 한 항목의 데이터 1바이트를 바꾼 `c_bad.zip`을 기본 옵션으로 복구하면 그 항목이 "CRC 오류"로 제외되고, "CRC가 맞지 않는 항목도 넣기"를 켜면 포함된다.
- [ ] AES-256으로 암호화된 `e_cut.zip`(CD 잘림)을 암호 없이 복구하면 사본이 만들어지고, 원래 암호로 사본을 풀 수 있다.
- [ ] 복구 전후 원본 파일의 SHA-256이 같다.
- [ ] 복구 중 취소하면 사본 파일이 남지 않는다.
- [ ] 7z 형식이나 분할 ZIP(`s.z01`, `s.zip`)에서는 S9-05가 비활성이고 각 툴팁이 보인다.
- [ ] 이름이 CP949인 `k_cut.zip`을 복구하면 사본의 이름 바이트가 원본과 같다(#17 감지 결과도 같다).
