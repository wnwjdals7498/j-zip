## 1. 목적

j-zip의 모든 화면을 사용자의 언어로 보여 준다. 7-Zip이 이미 가진 번역 파일(`Lang\*.txt`, 80개 이상 언어)을 그대로 재사용하고, j-zip이 새로 만든 문구(S1~S9, D1~D3)는 같은 파일 형식의 보충 파일로 번역한다. 그래서 7-Zip 번역가가 쓰던 방식 그대로 j-zip 번역에 참여할 수 있다. 언어 선택은 S8 화면·언어 탭에 둔다.

## 2. 현재 7-Zip 동작

- 번역 파일 위치: 실행 폴더 아래 `Lang\<언어 코드>.txt` (`CPP/7zip/UI/FileManager/LangUtils.cpp:33-36` `GetLangDirPrefix()`). 소스 레포에는 `Lang\*.txt`가 없고(`DOC/`에도 없음) 공식 바이너리 배포판에만 들어 있다(LGPL).
- 파일 형식(`CPP/Common/Lang.cpp` `CLang::OpenFromString`): UTF-8 텍스트. 첫 줄은 `;!@Lang2@!UTF-8!` 서명이어야 한다. `;`로 시작하는 줄은 주석. 숫자만 있는 줄은 "다음 문구의 ID"를 지정하고, 그 뒤의 문구 줄은 ID가 1씩 늘며 이어진다. 빈 줄은 ID 하나를 건너뛴다(번역 없음). 문구 안의 `\n`, `\t`, `\\`는 이스케이프로 해석된다. ID 상한은 2^30이고, 파일 크기는 1 MiB 이하여야 한다.
- 파일 식별: ID 0의 문구가 로더에 넘긴 식별 문자열("7-Zip")과 같아야 열린다(`LangUtils.cpp`의 `LangOpen`이 `lang.Open(fileName, "7-Zip")` 호출). 다르면 그 파일은 무시된다.
- 조회: `CLang::Get(id)`가 ID로 문구를 찾고, 없으면 NULL을 돌려준다. 호출부(`LangString`)는 NULL이면 프로그램에 내장된 리소스 문구(영어)를 쓴다. 7-Zip에는 영어용 번역 파일이 없다(영어 = 내장 리소스).
- 언어 선택: 레지스트리 값 `Lang`(`g_LangID`)을 읽는다(`ReloadLang`). 비어 있으면 Windows 언어로 자동 선택(`OpenDefaultLang`, 언어 코드 표 `kLangs`로 `ko.txt` 등 이름을 정함). `-`이면 번역 파일 없이 영어. 그 외 값은 파일 이름으로 본다.
- 사용자 입장: 설정의 언어 탭(`LangPage.cpp`)에서 언어를 고르면 다음 창부터 바뀐다.

## 3. 요구사항

- FR-22-1 S8-09 화면·언어 탭에 언어 드롭다운(S8-15)을 둔다. 첫 항목은 "시스템 설정 따르기"이며 기본값이다.
- FR-22-2 "시스템 설정 따르기"는 Windows 표시 언어에 맞는 7-Zip 번역 파일을 고르고(7-Zip의 언어 코드 표를 이식해 쓴다), 없으면 영어를 쓴다.
- FR-22-3 언어 목록은 패키지의 `Lang\` 폴더에 있는 파일에서 만들고, 각 언어 이름은 그 파일에 적힌 그 언어 이름으로 표시한다(예: "한국어", "English").
- FR-22-4 j-zip이 새로 만든 모든 문구(06 문서 S1~S9 요소의 문구)는 숫자 ID를 가진다. 소스 코드에 사용자에게 보이는 한국어·영어 문자열을 직접 쓰지 않는다.
- FR-22-5 j-zip은 최소한 한국어와 영어의 j-zip 보충 번역을 함께 배포한다. 7-Zip 번역 파일은 공식 배포판의 것을 수정 없이 함께 배포한다.
- FR-22-6 언어를 바꾸고 S8-10 [저장]하면 열려 있는 모든 j-zip 창의 문구가 앱을 다시 시작하지 않고 바뀐다(8절 수용 기준). 코드에서 조합한 동적 문구(진행 문구 등)는 다음에 갱신될 때 바뀔 수 있다.
- FR-22-7 선택한 언어에 없는 ID는 영어 문구로 표시한다(5절 대체 순서).
- FR-22-8 셸 메뉴(S7) 문구도 같은 언어 설정과 같은 번역 파일을 따른다.
- FR-22-9 7-Zip의 기존 문구는 7-Zip의 숫자 ID를 그대로 쓴다. j-zip 신규 문구는 7-Zip 기존 ID와 겹치지 않는 예약 범위(100000번 이상)를 쓴다.

## 5. 동작 규칙과 예외

- 문구 길이는 영어 기준 +30% 여유를 둔다(06 문서 2절). 번역이 길어 넘치면 줄임표 대신 줄바꿈 또는 툴팁으로 전체를 보인다.
- 오른쪽에서 왼쪽으로 쓰는 언어(아랍어 등)의 레이아웃 반전은 범위 밖이다.
- 대체 순서: 선택한 언어의 파일(7-Zip 파일 → j-zip 보충 파일) → 영어(7-Zip 기존 문구는 내장 영어 리소스, 신규 문구는 `Lang\jzip\en.txt`) → 내장 기본값(`jzip-shared`에 컴파일된 영어 최소 문구표. 파일이 모두 없거나 깨졌을 때도 앱이 뜨게 한다). 번역이 없는 ID는 조용히 영어로 보이며 오류로 취급하지 않는다.
- 번역하지 않은 신규 문구: 보충 파일에서 해당 줄을 빈 줄로 두거나 줄 자체를 두지 않는다. 7-Zip 파일 형식에서 빈 줄은 ID를 건너뛰므로 조회 결과가 없어 영어로 대체된다. 7-Zip 번역 파일에는 j-zip 신규 ID가 없으므로 신규 문구는 보충 파일이 없는 언어에서 모두 영어로 보인다.
- 번역 파일이 깨졌거나(서명 불일치, ID 0 불일치, 1 MiB 초과) 열 수 없으면 그 파일은 건너뛰고 대체 순서를 따른다. 사용자에게 오류 창을 띄우지 않는다.
- 번역 참여: 번역가는 7-Zip과 같은 형식으로 `Lang\jzip\<언어 코드>.txt`만 작성하면 된다. 기존 7-Zip 번역은 7-Zip 쪽 파일을 그대로 쓰므로 j-zip에서 고치지 않는다. 신규 ID 목록(영어 원문 포함)은 `Lang\jzip\en.txt`가 기준이며, 빌드 과정에서 언어별로 번역이 빠진 ID 수를 보고한다.

## 7. 구현 지점

- `jzip-shared`(`src/shared/i18n/`): 7-Zip `CPP/Common/Lang.cpp`의 `CLang` 파싱(`OpenFromString`의 서명·주석·ID·이스케이프·크기 상한 규칙, ID 0 식별 문자열 확인, `Get(id)` 조회)을 이식한 파서, `LangUtils.cpp`의 `kLangs` 표(언어 코드 → 파일 이름), 내장 영어 최소 문구표. OS를 호출하지 않으며 파일 읽기는 주입된 포트로 한다.
- `jzip-win`(`src/shared-win/`): 파일 읽기 포트의 Win32 구현(공유 읽기, 마지막 캐시)과 Windows 표시 언어 조회("시스템 설정 따르기"). 앱의 현지화 서비스와 셸이 같이 쓴다.
- `jzip-core`: 현지화 서비스만 둔다. 언어 폴더 경로는 `JZip.exe`가 `GetCurrentPackagePath`로 구해 주입한다. 언어 선택은 `LangUtils.cpp`(`GetLangDirPrefix`, `ReloadLang`, `OpenDefaultLang`)를 이식하고, 파일 로드는 `jzip-win` 파일 읽기, 파싱은 `jzip-shared` 파서로 한다. Win32 대화상자 컨트롤에 직접 글자를 넣는 함수(`LangSetDlgItems` 등)는 이식하지 않는다. 서비스는 `Get(id)` 하나로 문구를 돌려주고, 언어가 바뀌면 변경 알림을 낸다.
- 파일 배치: 7-Zip 번역 파일은 `Lang\<코드>.txt`(공식 바이너리 배포판에서 가져와 수정 없이 포함), j-zip 보충 파일은 `Lang\jzip\<코드>.txt`(같은 형식, ID 100000 이상, 보충 파일의 ID 0 식별 문자열은 `j-zip`). 보충 파일을 7-Zip 파일과 분리한 이유: (1) 7-Zip 번역 파일을 새 배포판 것으로 그대로 교체할 수 있고, (2) LGPL 파일을 수정하지 않은 채 배포할 수 있고, (3) j-zip 번역가가 7-Zip 번역과 상관없이 작업할 수 있다. 같은 파일 안에 예약 범위를 두는 방식은 7-Zip 파일을 수정해야 하므로 택하지 않는다. 조회는 선택 언어의 7-Zip 파일과 보충 파일을 둘 다 열어 ID로 찾는다(ID 범위가 겹치지 않으므로 합쳐도 충돌하지 않는다).
- `JZip.exe`(WinUI 3): 문구를 MRT `.resw`가 아니라 현지화 서비스에서 얻는다. XAML은 서비스가 노출하는 문구 인덱서에 바인딩(변경 알림 지원)하므로 언어를 바꾸면 앱을 다시 시작하지 않고 바인딩된 문구가 다시 그려진다. S8 화면·언어 탭(S8-09, S8-15)을 새로 만든다. 7zFM의 `LangPage.cpp`는 현재 동작 근거로만 쓴다.
- MSIX 매니페스트: 앱 이름·설명·파일 형식 표시 이름처럼 매니페스트가 요구하는 표시 문구만 `.resw`/`resources.pri`로 둔다(매니페스트의 `ms-resource:`가 그 방식만 받는다). 이 문구는 Windows 표시 언어에 맞게 정해지며 S8-15와 연동하지 않는다.
- `jzip-shell.dll`(S7 문구): `jzip-core`는 링크하지 않고 `jzip-shared`의 같은 파서와 `jzip-win` 파일 읽기를 링크해 자기 모듈 폴더 기준 `Lang\`를 읽는다. `Ui.Language` 값은 [08. 아키텍처](../08-architecture.md) 6절 규칙(셸 확장 경로·캐시)으로 `settings.json`에서 읽으며, 파일 수정 시각이 바뀌면 다시 읽어 탐색기를 재시작하지 않고 반영한다.
- 7-Zip 번역 파일 출처·라이선스: 공식 바이너리 배포판(LGPL)에서 가져온다. 소스 레포에 들어 있지 않으므로 빌드 단계에서 배포판의 `Lang` 폴더를 받아 패키지에 넣는다. LGPL 고지는 `THIRD_PARTY_NOTICES.md`에 넣는다(법률 자문은 아니다).

## 8. 수용 기준

- [ ] Windows 표시 언어 한국어에서 처음 실행하면 S1이 한국어다(7-Zip `ko.txt` + j-zip 보충 `ko.txt`).
- [ ] Windows 표시 언어 영어에서 처음 실행하면 S1이 영어다.
- [ ] S8-15에서 "English"를 고르고 저장하면 열린 S1의 툴바 라벨과 열린 S8 창의 문구가 앱을 다시 시작하지 않고 영어로 바뀐다.
- [ ] 번역 파일이 없는 언어(예: 아이슬란드어 파일을 제거한 상태)인 Windows에서 "시스템 설정 따르기"이면 영어로 보인다.
- [ ] 7-Zip 번역이 있고 j-zip 보충 파일이 없는 언어(예: 일본어)를 고르면 7-Zip에서 온 문구(예: 확인·취소)는 일본어, j-zip 신규 문구는 영어로 보인다.
- [ ] 한국어 보충 파일에서 S2-05 줄을 빈 줄로 만들면 그 문구만 영어로 보인다.
- [ ] 서명 줄을 지운 깨진 `Lang\xx.txt`를 고르면 오류 창 없이 영어로 보인다.
- [ ] 언어를 바꾼 뒤 탐색기 우클릭(S7) 문구도 탐색기 재시작 없이 바뀐다.
- [ ] 패키지의 7-Zip `Lang\*.txt`가 공식 배포판의 것과 바이트 단위로 같다.

## 9. 범위 밖·미결 사항

- 범위 밖: 한국어·영어 이외 언어의 j-zip 보충 번역 작업 자체(7-Zip 번역은 재사용), RTL 레이아웃.
- 해결(사용자 결정): 7-Zip `Lang\*.txt` 번역 파일을 런타임에 읽는 방식으로 재사용한다. 문구는 MRT `.resw`가 아니라 현지화 서비스에서 얻는다(7절). MRT Core의 실행 중 언어 변경 문제는 이 결정으로 사라졌다.
- 해결: 셸 확장(`jzip-shell.dll`, S7)은 앱과 같은 `settings.json`을 읽는다. 경로 유도·공유 읽기·캐시 규칙은 [08. 아키텍처](../08-architecture.md) 6절.
- 해결: ID 범위 — 7-Zip 26.04 소스의 리소스·문구 ID 최댓값은 7822(`CPP/**/*.h`의 `IDS_`/`IDX_`/`IDT_`/`IDC_`/`IDM_`/`IDB_` 정의 기준)이므로 100000 이상 예약 범위는 겹치지 않는다.
- 미결: 7-Zip 번역 파일 중 j-zip 화면에 그대로 쓸 수 있는 문구의 비율은 공식 배포판을 받아 확인한다. 이 비율은 j-zip 신규 문구 수에만 영향을 주고 설계에는 영향이 없다.
- 06에 반영됨 (S8-14 테마, S8-15 언어). Settings 디자인의 화면·언어 탭 아트보드는 디자인 쪽에서 추가한다.
