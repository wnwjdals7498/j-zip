## 1. 목적

압축 파일 안의 문서를 고치려면 풀고, 고치고, 다시 넣어야 한다. 7-Zip은 이를 F4로 일부 해 주지만, 편집기를 닫은 뒤에야 묻고, 같은 편집기가 이미 떠 있으면 종료를 감지하지 못하는 경우가 있다.
j-zip은 파일 저장 자체를 감시해 저장할 때마다 갱신 여부를 물어 사용자가 편집기를 닫지 않아도 아카이브에 반영되게 한다.

## 2. 현재 7-Zip 동작

- `CPP/7zip/UI/FileManager/PanelItemOpen.cpp:48` `kTempDirPrefix "7zO"`: 임시 폴더 접두사.
- `:1484` `CPanel::OpenItemInArchive`: 항목을 임시 폴더에 풀고 외부 프로그램을 실행한다.
- `:1133` `MyThreadFunction`: 실행한 프로세스가 끝날 때까지 기다리고, 파일이 바뀌었으면 `IDS_WANT_UPDATE_MODIFIED_FILE`로 갱신 여부를 묻는다(`:1281`).
- `:1037` `CPanel::OnOpenItemChanged`: 아카이브 갱신.
- `:719` `StartEditApplication`: 편집기 실행. 메뉴 명령은 `IDM_FILE_EDIT`.
- `:1328`: 임시 파일에 `:Zone.Identifier`를 복사한다(#21 MOTW).
- 사용자 입장: 편집기 프로세스가 끝나야 질문이 나온다. 이미 실행 중인 편집기에 문서가 열리면(단일 인스턴스 앱) 프로세스가 바로 끝나 변경을 놓칠 수 있다(아래 9절 참고).

## 3. 요구사항

- FR-15-1 S1-20 "기본 앱으로 열기"와 `F4`는 선택한 파일 1개를 임시 폴더에 풀어 Windows 기본 연결 앱으로 연다. `F3`(보기)는 읽기 전용으로 열고 갱신을 감시하지 않는다.
- FR-15-2 열린 임시 파일의 마지막 수정 시각과 크기를 감시하고, 저장이 감지되면 1초 동안 추가 변경이 없을 때 S1에 갱신 확인을 띄운다.
- FR-15-3 확인 문구: "{파일 이름}이 바뀜 · 압축 파일에 반영할까요?" 버튼 [반영 안 함] [반영]. "이 파일은 묻지 않고 반영" 체크박스를 둔다.
- FR-15-4 반영을 고르면 S4로 진행 상황을 보이며 해당 항목을 교체한다. 반영 후에도 감시를 계속하므로 다시 저장하면 다시 묻는다.
- FR-15-5 감시는 S1에서 그 아카이브 탭을 닫거나 j-zip을 끝낼 때 멈춘다. 반영하지 않은 변경이 있으면 닫기 전에 "반영하지 않은 변경 N개가 있음"을 묻는다.
- FR-15-6 쓰기를 지원하지 않는 형식(#14 FR-14-5)에서는 S1-20 문구를 "기본 앱으로 열기 (읽기 전용)"으로 바꾸고 감시하지 않는다.
- FR-15-7 임시 폴더는 감시가 끝나면 지운다. 반영하지 않은 변경이 남은 상태로 닫기를 고르면 임시 파일을 지우기 전에 경고한다.

## 5. 동작 규칙과 예외

- 여러 파일을 동시에 열어 각각 감시할 수 있다. 감시 대상마다 독립적으로 묻는다.
- 아카이브 원본이 다른 프로그램에 의해 바뀌었으면(수정 시각 변경) 반영 전에 "압축 파일이 바뀌었음"을 알리고 반영하지 않는다.
- 암호 아카이브: 열 때 쓴 암호로 다시 압축한다. 암호를 다시 묻지 않는다.
- 반영 실패(디스크 부족, 읽기 전용 위치)이면 임시 파일을 지우지 않고 그 경로를 오류 메시지에 보여 준다.
- MOTW: 기존 7-Zip처럼 아카이브의 `Zone.Identifier`를 임시 파일에 복사한다(`PanelItemOpen.cpp:1328`).

## 7. 구현 지점

- `jzip-core` 로직(임시 추출·기본 앱 실행·변경 감시·갱신)과 `JZip.exe`(WinUI 3) S1-20·D1 화면. 기존 파일 `CPP/7zip/UI/FileManager/PanelItemOpen.cpp`의 아래 동작을 근거로 옮긴다.
  - `MyThreadFunction`(`:1133`): 프로세스 종료 대기 동작. j-zip은 대신(또는 함께) 파일 변경 감시를 한다.
  - `CPanel::OnOpenItemChanged`(`:1037`): 갱신 동작. j-zip은 반복 호출할 수 있게 한다.
  - `CPanel::OpenItemInArchive`(`:1484`), `StartEditApplication`(`:719`): 기본 앱 실행 경로.
  - `IDS_WANT_UPDATE_MODIFIED_FILE`(`:1281`): 현재 질문 문구. j-zip D1-01 문구는 FR-15-3을 따른다.

## 8. 수용 기준

- [ ] `doc.zip` 안 `memo.txt`를 S1-20으로 열어 메모장에서 내용을 바꿔 저장하면, 메모장을 닫지 않아도 갱신 확인이 뜬다.
- [ ] [반영]을 누른 뒤 `doc.zip`을 새로 열어 `memo.txt`를 보면 바뀐 내용이다.
- [ ] 같은 파일을 다시 저장하면 다시 묻는다.
- [ ] "이 파일은 묻지 않고 반영"을 켠 뒤 저장하면 묻지 않고 반영된다.
- [ ] 반영하지 않은 변경이 있는 상태에서 S1 탭을 닫으면 경고가 뜬다.
- [ ] `x.iso` 안 파일에서 S1-20 문구가 "(읽기 전용)"이고 저장해도 묻지 않는다.
- [ ] 반영 후 `7z t doc.zip`이 오류 없이 끝난다.

## 9. 범위 밖·미결 사항

- 범위 밖: 아카이브 안에서 새 파일 만들기.
- 미결: 파일 변경 감시 방식(`ReadDirectoryChangesW` 또는 주기적 확인). research 자료에는 근거가 없다. 일부 편집기는 저장할 때 임시 파일을 만들고 이름을 바꾸므로 이름 변경도 감지해야 한다.
- 미결: 단일 인스턴스 앱에서 기존 `MyThreadFunction`이 변경을 놓치는지는 소스상 대기 방식으로 추정한 것이며, 실제 재현은 하지 않았다.
- 06에 반영됨 (D1-01, D1-02, D1-03, D1-04, S8-21)
- 해결: S1-20 문구는 "기본 앱으로 열기", 기본 동작은 반영 전에 묻기(D1), 자동 반영은 설정(S8-21)으로 정했다. Main 디자인의 "(편집하면 자동 갱신)" 문구는 디자인 쪽에서 고친다.
