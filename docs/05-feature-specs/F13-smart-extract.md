## 1. 목적

아카이브를 "여기에 풀기"로 풀면 최상위 항목이 수십 개일 때 현재 폴더가 어지러워지고, "이름 폴더에 풀기"로 풀면 `자료\자료\…`처럼 폴더가 이중으로 생기는 일이 잦다.
스마트 해제는 아카이브의 최상위 항목 수를 먼저 보고, 하나면 그대로, 여러 개면 아카이브 이름 폴더를 만들어 푼다.
사용자는 풀기 전에 매번 아카이브 안을 확인하지 않아도 되고, 결과 경로를 S2에서 미리 볼 수 있다.

## 3. 요구사항

- FR-13-1 폴더 만들기 방식은 세 가지다: `smart`(스마트), `always`(항상 아카이브 이름 폴더), `none`(폴더 없이). 기본값은 `smart`.
- FR-13-2 `smart`에서 아카이브의 최상위 항목(경로의 첫 구성 요소 기준, 중복 제거)이 정확히 1개이면 풀 위치(S2-02 또는 우클릭한 폴더)에 그대로 푼다. 2개 이상이면 `풀 위치\{아카이브 이름}\`을 만들고 그 안에 푼다.
- FR-13-3 최상위 항목 수를 셀 때 디렉터리 항목과 파일 항목의 경로를 모두 쓰며, 디렉터리 항목이 따로 없어도 `a\b.txt`는 최상위 항목 `a`로 센다.
- FR-13-4 `smart`에서 최상위 항목이 하나뿐이어도, 풀 위치에 같은 이름의 파일·폴더가 이미 있으면 기존 항목에 섞지 않고 `풀 위치\{아카이브 이름}\` 폴더를 만들어 푼다. 이 폴더도 이미 있으면 `{아카이브 이름} (2)`, `(3)` …으로 비어 있는 이름을 고른다.
- FR-13-5 `always`에서 아카이브의 유일한 최상위 폴더 이름이 아카이브 이름과 같으면 기존 `ElimDup`과 같이 이중 폴더를 만들지 않는다.
- FR-13-6 `none`은 현재 "여기에 풀기"와 같다(풀 위치에 그대로).
- FR-13-7 "{아카이브 이름}"은 확장자를 뺀 이름이다. 기존 `GetSubFolderNameForExtract` 규칙을 그대로 쓴다(예: `자료.zip` → `자료`, 분할 `자료.7z.001` → 기존 규칙의 결과).
- FR-13-8 S2-05 결과 미리보기는 S2-02 또는 S2-04가 바뀌면 즉시 실제로 만들어질 최상위 경로 한 줄과 판단 근거("맨 위 항목 N개를 묶음" / "맨 위 폴더가 하나라 그대로 풂")를 다시 그린다.
- FR-13-9 S7-01 "여기에 풀기 (스마트)"는 대화상자 없이 `smart` 규칙으로 우클릭한 폴더에 푼다. S7-02 "{이름}\에 풀기"는 `always` 규칙을 쓴다.
- FR-13-10 여러 아카이브를 선택했을 때(S7-10 "각각 폴더로 풀기 (N개)") 아카이브마다 `smart` 판단을 따로 한다.
- FR-13-11 암호로 이름이 숨겨진 7z(헤더 암호화)처럼 항목 목록을 풀기 전에 읽을 수 없으면 암호 입력(S6) 뒤에 판단한다. 암호 입력을 취소하면 풀기 자체를 취소한다.
- FR-13-12 CLI에서도 같은 판단을 쓸 수 있게 새 스위치를 둔다(이름은 9절 미결 사항). 기존 `-spe` 동작은 바꾸지 않는다.

## 5. 동작 규칙과 예외

- 최상위 항목이 0개(빈 아카이브)이면 폴더를 만들지 않고, S4 완료 요약에 "풀 항목이 없음"을 표시한다.
- 최상위 항목 이름 비교는 대소문자 구분 없이 한다(Windows 파일 시스템 기준). `A\x`와 `a\y`는 최상위 항목 1개다.
- 경로가 `..`나 절대 경로로 시작하는 항목은 기존 7-Zip 경로 정리 규칙을 따르며, 정리된 결과 경로로 최상위 항목을 센다.
- `.tar.gz` 한 번에 풀기(#12)가 켜져 있으면 바깥 gz가 아니라 안쪽 tar의 최상위 항목으로 판단한다.
- 선택 항목만 풀기(S1-19)에서는 선택 항목 기준으로 센다.
- 대체 데이터 스트림(alt stream) 항목은 세지 않는다.
- 풀기 중 오류가 나서 일부만 풀린 경우에도 이미 만든 폴더는 지우지 않는다.
- FR-13-4 충돌 회피로 폴더 이름이 바뀌었으면 S4 완료 요약에 실제 경로를 표시한다.
- 끝나면 폴더 열기(#30)는 스마트 판단 결과의 최상위 경로(폴더를 만들었으면 그 폴더, 아니면 단일 항목)를 연다.

## 9. 범위 밖·미결 사항

- 범위 밖: 아카이브 안 구조를 바꿔 푸는 기능(특정 하위 폴더만 꺼내기 등).
- 미결: CLI 스마트 스위치 이름. 기존 스위치와 겹치지 않는 이름을 정해야 하며, research 자료에는 후보가 없다.
- 미결: FR-13-4 충돌 시 묻지 않고 이름 폴더로 우회하는 것이 맞는지, S2-09 "같은 파일 처리" 값을 따라야 하는지. 이 문서는 기존 데이터 보호를 우선해 우회로 정했다.
- 미결: 항목 목록을 얻으려면 전체를 읽어야 하는 스트림형 형식(예: #12가 켜진 `.tar.gz`)에서 판단 비용. research 자료에는 tar.gz 안쪽 목록을 미리 얻는 경로가 없으므로, 임시 폴더에 푼 뒤 옮기는 방식이 필요할 수 있다.
- 06에 반영됨 (S1-02 `▾` 첫 항목 "여기에 풀기 (스마트)")
- 해결: 06·04의 S7-11 `기능`을 #18 #34로 고쳤고, 04의 하위 메뉴 이름을 "j-zip ▸"로 맞췄다. ContextMenu 디자인 파일의 "7-Zip" 표기는 디자인 쪽에서 고친다.
