# OPS. 진단·로그 운영

| 항목 | 내용 |
|---|---|
| 기능 번호 | OPS (기능 벤치마크 #1–#36 밖의 운영 기능) |
| 우선순위 | — (G0에 로그 뼈대, G4에 화면) |
| 7-Zip 26.04 | ❌ — 진단 로그, 로그 내보내기 기능 없음 |
| 반디집 참고 | 해당 없음 (j-zip 운영 요구) |
| 화면 | S8 설정 (일반 탭) |
| GUI 요소 | S8-22, S8-23, S8-24 |
| 디자인 파일 | 해당 없음 — Settings.dc.html에 이 항목이 없다. 06 정의를 기준으로 한다 |
| 관련 기능 | #23(암호는 내보내지 않음), 전체(운영 로그) |

## 1. 목적

사용자가 문제를 겪을 때 개발자가 원인을 재현할 수 있도록, 사용자가 직접 켜고 끄는 진단 로그와 한 번에 첨부할 수 있는 로그 묶음을 제공한다.
j-zip은 원격 수집(텔레메트리)을 하지 않으므로, 로그는 사용자 PC에만 남고 사용자가 내보내기로 직접 전달한다.
경로·파일 이름 같은 개인정보는 기본적으로 남기지 않는다. 운영 체계 전체는 [10. 로그·증거·운영](../10-logging-evidence-operations.md) 2절, 7절에 있다.

## 2. 현재 7-Zip 동작

해당 없음. 7-Zip 26.04에는 진단 로그 기록·내보내기 설정이 없다(research 자료에 관련 항목 없음).

## 3. 요구사항

### 기본 상태

- FR-OPS-1 j-zip은 어떤 로그도 네트워크로 보내지 않는다(텔레메트리 없음).
- FR-OPS-2 진단 모드가 꺼져 있어도 Error·Warning 이벤트는 `LocalState\logs\errors.log`에 남긴다. 이 파일은 1MB에서 순환하며 경로·파일 이름을 담지 않는다(이벤트 이름, 오류 코드, 확장자, 시각만).
- FR-OPS-3 진단 모드가 꺼져 있으면 Info·Verbose 파일 로그를 쓰지 않는다.

### 진단 모드 (S8-22)

- FR-OPS-4 S8-22 "진단 로그 기록"을 켜면 Info·Verbose 이벤트를 `LocalState\logs\jzip-<YYYYMMDD>-<n>.log`에 기록한다. 파일당 5MB, 최대 5개를 순환한다.
- FR-OPS-5 진단 모드를 켠 시각을 설정에 저장하고, 앱 시작 때와 실행 중 하루 한 번 검사해 켠 지 7일이 지났으면 자동으로 끈다. 켜져 있는 동안 S8-22 옆에 남은 기간("N일 남음")을 표시한다.
- FR-OPS-6 "경로 포함"(기본 꺼짐)이 꺼져 있으면 로그에 경로를 원문으로 쓰지 않는다. 같은 경로인지 구별해야 하는 필드는 HMAC-SHA256 값으로 쓰고, 그 밖에는 확장자·경로 깊이·길이만 쓴다.
- FR-OPS-7 HMAC 키는 설치마다 무작위로 만들어 `LocalState`에 둔다. 진단 모드를 켤 때마다 새 키를 만든다(이전 진단 기간의 해시와 연결되지 않게).
- FR-OPS-8 "경로 포함"을 켜면 그 진단 기간 동안만 경로 원문을 기록한다. 진단 모드가 꺼지면(수동·자동) "경로 포함"도 꺼진다.

### 로그 내보내기 (S8-23)

- FR-OPS-9 S8-23 "로그 내보내기…"는 저장 위치를 고르게 한 뒤 zip 파일 하나를 만든다. 내용: 진단 로그 파일 전부, `errors.log`, 설정 파일 사본, 버전 정보 파일.
- FR-OPS-10 암호 저장 파일(`passwords.json`, #23)과 HMAC 키 파일은 어떤 경우에도 넣지 않는다. 설정 사본(`settings.json`)에는 암호 값이 없으며(#23 암호는 설정 파일에 저장하지 않음), `Password.*` 키는 켜기/끄기·개수 같은 동작 설정만 담는다.
- FR-OPS-11 설정 스키마에서 `pii: true`로 표시된 키(최근 경로, 마지막 풀 위치 등, [08](../08-architecture.md) 6절)는 "경로 포함"이 꺼져 있으면 내보내는 설정 사본에서 뺀다.
- FR-OPS-12 버전 정보 파일에는 앱 버전, 커밋 SHA, 7-Zip 기준 버전, Windows App SDK 버전, OS 빌드·아키텍처를 적는다.
- FR-OPS-13 내보낸 zip 파일 이름은 `jzip-logs-<YYYYMMDD-HHMMSS>.zip`이다. 기존 파일이 있으면 덮어쓰지 않고 `(2)`, `(3)` …을 붙인다.

### 버전 표시

- FR-OPS-14 앱의 정보 화면(S8-24)에 FR-OPS-12와 같은 버전 정보를 표시한다.

## 4. GUI 명세

| ID | 상태·표시 조건 | 문구 | 동작 |
|---|---|---|---|
| S8-22 | 설정 › 일반 | "진단 로그 기록"(기본 꺼짐) + "경로 포함"(기본 꺼짐). 켜져 있으면 "N일 남음" | FR-OPS-4~FR-OPS-8. "경로 포함"은 "진단 로그 기록"이 켜져 있을 때만 활성 |
| S8-23 | 설정 › 일반 | "로그 내보내기…" | 저장 위치 선택 → FR-OPS-9~FR-OPS-13. 끝나면 저장한 파일을 탐색기에서 선택한 상태로 연다 |
| S8-24 | 설정 › 일반, 탭 맨 아래 | 정보: 앱 버전, 커밋 SHA, 7-Zip 기준 버전, Windows App SDK 버전, 라이선스·오픈소스 고지(`THIRD_PARTY_NOTICES`) 링크, LGPL 소스 공개 링크 | 표시만(FR-OPS-14). 값은 FR-OPS-12 버전 정보 파일과 같다 |

## 5. 동작 규칙과 예외

- 로그 폴더를 만들 수 없거나 쓰기에 실패하면 파일 로그만 건너뛰고 앱 동작은 계속한다. 이 실패 자체는 ETW로만 남긴다.
- 내보내기 중 진단 로그 파일이 쓰이는 중이면 공유 읽기로 열어 그 시점 내용을 넣는다.
- 진단 로그 파일이 하나도 없으면(진단 모드를 켠 적이 없음) `errors.log`, 설정 사본, 버전 정보만 넣고 정상 완료한다.
- 셸 확장(`jzip-shell.dll`)은 파일 로그를 쓰지 않는다(ETW만, [10](../10-logging-evidence-operations.md) 2.1). 따라서 내보내기에는 셸 확장 로그가 없다.
- 크래시 덤프는 내보내기에 넣지 않는다. 덤프 수집 방식은 G0 검증 후 확정한다([10](../10-logging-evidence-operations.md) 2.4).

## 6. 설정

| 키 | 기본값 | 위치(S8 탭) | 설명 |
|---|---|---|---|
| `Diagnostics.Enabled` | 꺼짐 | 일반 (S8-22) | 진단 모드 |
| `Diagnostics.EnabledAt` | (없음) | (화면 없음) | 진단 모드를 켠 시각. 7일 자동 꺼짐 계산용 |
| `Diagnostics.IncludePaths` | 꺼짐 | 일반 (S8-22) | 경로 원문 포함 |

HMAC 키는 설정 파일이 아니라 `LocalState`의 별도 파일에 두며 내보내기에 넣지 않는다.

## 7. 구현 지점

- `jzip-core` `infra/log/`: `ILogger` 파일 로그 구현(순환, `errors.log`, 진단 모드 판단, HMAC 경로 필드). `jzip-shared`·`jzip-core` 코드는 `ILogger` 포트로만 로그를 낸다([08](../08-architecture.md) 3절).
- `jzip-core` `app/settings/`: 진단 키 저장, 7일 자동 꺼짐 검사(앱 시작 + 하루 한 번 타이머는 `JZip.exe`가 호출).
- `jzip-core`: 내보내기 작업(zip 작성은 7-Zip 엔진 어댑터 사용, `pii` 필터는 `jzip-shared` 설정 스키마를 읽음).
- `JZip.exe`(WinUI 3) S8 일반 탭: S8-22, S8-23, S8-24를 새로 만든다. 저장 위치 선택은 파일 저장 대화상자.
- ETW 공급자 정의·등록은 바이너리별로 한다([10](../10-logging-evidence-operations.md) 2.1).

## 8. 수용 기준

- [ ] 새로 설치한 상태에서 압축을 하나 풀면 `LocalState\logs\`에 `jzip-*.log`가 생기지 않는다.
- [ ] 손상 ZIP을 풀어 오류가 나면 `errors.log`에 오류 이벤트가 남고, 그 줄에 아카이브 경로·파일 이름이 없다.
- [ ] S8-22를 켜고 압축을 풀면 `jzip-<날짜>-1.log`에 `Extract.Start`·`Extract.End`가 기록되고, 경로 필드는 원문이 아니라 HMAC 값이다.
- [ ] 진단 모드를 켠 시각을 8일 전으로 둔 설정으로 앱을 시작하면 진단 모드가 꺼져 있고 S8-22 체크가 해제돼 있다.
- [ ] 앱을 계속 실행한 채 켠 지 7일이 지나면(시계 포트로 시간 이동) 하루 한 번 검사에서 진단 모드가 꺼진다.
- [ ] 진단 모드를 껐다 다시 켜면 같은 경로의 HMAC 값이 이전 기간과 다르다.
- [ ] "경로 포함"을 켜면 로그에 경로 원문이 나오고, 진단 모드를 끄면 "경로 포함"도 꺼진다.
- [ ] S8-23으로 내보낸 zip에 진단 로그, `errors.log`, 설정 사본, 버전 정보가 있고, `passwords.json`과 암호 값이 없다.
- [ ] "경로 포함"이 꺼진 상태에서 내보낸 설정 사본에 `pii: true` 키(최근 경로 등)가 없고, 켠 상태에서는 있다.
- [ ] 버전 정보 파일의 앱 버전·커밋 SHA가 정보 화면 표시와 같다.
- [ ] 내보내기 중 네트워크 연결이 생기지 않는다(E6 시스템 변화 캡처로 확인).

## 9. 범위 밖·미결 사항

- 범위 밖: 원격 수집(텔레메트리), 자동 오류 보고 업로드, 셸 확장 파일 로그.
- 해결: 정보 화면은 06 S8-24로 추가했다(FR-OPS-14).
- 미결: 크래시 덤프를 내보내기에 넣을지는 G0 크래시 수집 검증(ADR) 뒤에 정한다. 덤프에는 암호 등 비밀이 들어 있을 수 있다.
