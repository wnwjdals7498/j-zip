## 1. 배경

### 1.1 왜 이 작업이 있나

CP949와 GBK는 바이트 범위가 거의 겹쳐서 한글 이름이 GBK로도 유효하게 디코딩된다. 그래서 점수기는 디코딩된 문자가 "그 언어의 상용 문자 상위 512자"에 드는 비율 `F`로 두 후보를 가른다([F17 FR-17-8](../../docs/05-feature-specs/F17-filename-encoding.md)). 점수기(G2-F17-T03)는 표를 주입받기만 하고 표가 없으면 `F = 1.0`으로 동작한다. 그 동안은 짧은 한글 이름에서 CP949와 GBK가 같은 점수로 동점이 될 수 있다. 이 카드가 **진짜 표**를 만든다: 어떤 원본에서 만들지, 그 라이선스가 j-zip(LGPL, 허용형 동봉만)에 맞는지 결정해 ADR로 남기고, 원본에서 상위 512자를 뽑는 생성 스크립트와 그 결과 표를 `jzip-shared`에 넣는다.

### 1.3 구현에 필요한 사실 (인라인)

- **표의 용도.** `F = (디코딩된 문자 중 0x80 이상 코드 단위가 표에 드는 수) / N`. 한글 표는 한글 음절(U+AC00–U+D7A3) 512자, 간체 표는 CJK 통합 한자(U+4E00–U+9FFF) 512자다(FR-17-7·8). "상위 512자"는 원본의 빈도(또는 순위)로 정한 1~512위다.
- **점수기와의 접점.** 이 카드는 `std::span<const char16_t>` 두 개(한글, 간체)를 **코드 포인트 오름차순**으로 낸다. G2-F17-T08이 그것을 `ICommonCharSet`으로 감싸 이분 탐색한다. 그래서 이 카드는 T03의 인터페이스에 의존하지 않는다.
- **진행 순서.** (가) 오케스트레이터가 원본을 고르고(PRE-1) ADR을 채택하고(PRE-2) 원본을 `third_party/`에 가져오고(PRE-3) 이 카드를 r1으로 개정한다(PRE-4). (나) 구현자가 생성 스크립트, 표 파일, 조회 코드, 기록 문서를 만든다(R-1~R-8). 원본 선택에는 네트워크와 라이선스 판단이 필요하므로 (가)는 구현자의 일이 아니다.
- **스크립트 위치.** `tools/`에는 이 용도의 폴더가 없다([09 2절](../../docs/09-development-process.md) 구조). 생성 스크립트는 생성 결과와 같은 `src/shared/encoding/tables/`에 둔다(제안, 카드 결정). 이 스크립트는 빌드에 쓰이지 않는다(표 파일을 커밋해 두고 `-Check`로 재현성만 검사한다).

### 1.4 작성 환경 한계

이 카드를 쓴 환경에는 C++ 컴파일러가 없어서 6.3절 선언을 컴파일해 보지 못했다. 원본은 PRE-1에서 정해지므로 이 카드는 6.1절 표의 값을 모른다. 8.2절의 합성 입력 기대값은 카드 작성자가 7.4절 규칙을 Python으로 옮긴 임시 스크립트로 계산했다(스크립트는 레포에 넣지 않는다). PowerShell 생성기는 이 환경에서 만들어 실행해 보지 않았다.

### 6.1 고정된 원본 — 확정(PRE-4에서 카드 r1이 채운다)

### 6.2 생성 스크립트 `generate-common-chars.ps1` — 제안(카드 결정, 규칙은 7.4절)

경로 `src/shared/encoding/tables/generate-common-chars.ps1`.

- 호출: `powershell -NoProfile -File src/shared/encoding/tables/generate-common-chars.ps1 [-Table ko|zh|all] [-Check] [-Count <n>] [-OutDir <경로>] [-SourceFile <경로> -Delimiter <값> -CharColumn <n> -ValueColumn <n> -ValueKind <값> -SkipLines <n>]`
- 기본값: `-Table all`, `-Count 512`, `-OutDir`은 스크립트가 있는 폴더, `-SourceFile`과 형식 인자는 6.1절 표의 값(스크립트 안의 `$Sources` 표에 옮겨 적는다).
- `-SourceFile`과 형식 인자는 시험용이다. `-Table ko` 또는 `-Table zh` 하나일 때만 쓸 수 있고, 주면 6.1절 값 대신 쓴다(원본 이름·버전·SPDX는 `$Sources`의 값을 헤더에 계속 쓴다).
- 출력 파일 이름은 고정이다: `korean_top512.inc`(`ko`), `simplified_chinese_top512.inc`(`zh`). `-OutDir`에 쓴다.
- 종료 코드: 0 = 성공(또는 `-Check`가 일치), 1 = 입력·검사 실패(7.4절 G-2·G-4·G-6), 2 = 사용법 오류(알 수 없는 `-Table` 값, `-SourceFile` 파일 없음, `-Table all`과 `-SourceFile` 동시 사용, 알 수 없는 `-ValueKind`·`-Delimiter` 값).
- 출력(표준 출력): 표마다 한 줄 `OK <ko|zh> selected=<n> skipped=<m> sha256=<입력 파일 해시>`. `-Check`일 때는 일치하면 `MATCH <ko|zh>`, 다르면 `MISMATCH <ko|zh>`.
- **파일은 ASCII만 쓴다.** Windows PowerShell 5.1이 BOM 없는 UTF-8을 ANSI로 읽기 때문이다. 입력 파일은 `[System.IO.File]::ReadAllText(<경로>, (New-Object System.Text.UTF8Encoding($false)))`로 UTF-8로 읽고, 출력은 ASCII 바이트로 `[System.IO.File]::WriteAllBytes`로 쓴다(줄 끝 LF).
- 스레드·성능: 단일 스레드, 입력 1MB 이하에서 10초 안에 끝난다.
- `.inc` 형식(그대로 만든다. `<…>` 값은 `$Sources`와 입력 파일에서 채운다):

```
// GENERATED by generate-common-chars.ps1 -- DO NOT EDIT.
// source: <원본 이름> <버전·태그·날짜> (<SPDX>), sha256 <입력 파일 SHA-256 소문자 16진>
// table: <ko|zh>, count: <n>, sorted by code point ascending
  0xAC00, 0xAC01, 0xAC04, 0xAC07, 0xAC08, 0xAC09, 0xAC0A, 0xAC10,
  ...
```

  데이터 줄은 들여쓰기 공백 2칸 + 값을 `, `로 이어 붙이고 끝에 `,`를 붙인다. 값은 `0x` + 대문자 16진 4자리. 한 줄에 8개이고 마지막 줄만 8개 미만일 수 있다(512개면 64줄). 파일 끝에 줄바꿈이 한 번 있다. 값은 코드 포인트 오름차순이다.

### 6.3 조회 함수 — 제안(카드 결정)

`src/shared/encoding/tables/common_char_tables.h`. 네임스페이스 `jzip::shared::encoding`. 6.3절 선언은 컴파일해 보지 못했다(1.4절).

```cpp
inline constexpr std::size_t kCommonCharCount = 512;

// 한글 음절(U+AC00-U+D7A3) 상위 512자. 코드 포인트 오름차순, 중복 없음.
std::span<const char16_t> KoreanCommonChars() noexcept;
// 간체 한자(U+4E00-U+9FFF) 상위 512자. 코드 포인트 오름차순, 중복 없음.
std::span<const char16_t> SimplifiedChineseCommonChars() noexcept;
```

- Input: 없음. Output: 정적 저장 기간 배열을 가리키는 `span`(길이 `kCommonCharCount`). 오류: 없음. 부작용: 없음(할당·OS 호출·전역 가변 상태 없음). 스레드: 읽기 전용이라 동시에 호출해도 안전하다. 수명: 프로그램 전체.
- `common_char_tables.cpp`는 `constexpr char16_t kKorean[] = { #include "korean_top512.inc" };`처럼 `.inc`를 포함하고, `static_assert`로 배열 길이가 `kCommonCharCount`와 같고 값이 엄격하게 오름차순이며 범위 안임을 컴파일 시점에 검사한다(헤더 구성은 구현자가 정한다. 위 선언과 동작이 계약이다).
- 이 헤더는 `ICommonCharSet`(G2-F17-T03)을 include하지 않는다.

### 7.4 생성 규칙 (G-1~G-7) — 제안(카드 결정, 숫자 512는 FR-17-8 확정)

| 규칙 | 내용 |

| G-1 읽기 | 입력 파일을 UTF-8로 읽고 BOM이 있으면 떼어 낸다. 줄 끝은 `\n`·`\r\n` 모두 받는다. 처음 `SkipLines`줄을 건너뛰고, 그 뒤의 빈 줄과 `#`로 시작하는 줄은 무시한다 |
| G-2 분리 | 줄을 `Delimiter`(`tab`은 탭 하나, `space`는 공백·탭 하나 이상, `comma`는 쉼표 하나)로 나눈다. `CharColumn`의 값이 UTF-16 코드 단위 정확히 1개가 아니면(단어, 서로게이트 쌍, 빈 값) 종료 코드 1. `ValueKind`가 `count`·`rank`이면 `ValueColumn`의 값을 정수로 읽고 실패하면 종료 코드 1. `order`이면 값을 읽지 않는다(파일 순서가 순위) |
| G-3 필터·중복 | `ko`는 U+AC00–U+D7A3, `zh`는 U+4E00–U+9FFF 안의 문자만 남기고 나머지는 건너뛴다(건너뛴 줄 수를 `skipped`로 센다). 같은 문자가 여러 줄이면 **첫 줄만** 쓴다. 필터 앞의 G-2 검사는 건너뛴 줄에도 적용된다 |
| G-4 정렬·선택 | `count`는 값 내림차순, `rank`는 값 오름차순, `order`는 파일 순서로 정렬한다. 같은 값은 코드 포인트 오름차순이다. 앞에서 `Count`개를 고른다. 남은 문자가 `Count`보다 적으면 종료 코드 1이고 어떤 파일도 쓰지 않는다. `Count` 경계에서 값이 같은 문자가 여럿이면 코드 포인트 오름차순으로 자른다 |
| G-5 출력 | 고른 문자를 코드 포인트 오름차순으로 정렬해 6.2절 `.inc` 형식으로 쓴다. 헤더에 시각·사용자 이름·경로를 넣지 않는다(결정적 출력). 같은 입력·같은 인자는 항상 같은 바이트를 낸다 |
| G-6 `-Check` | 파일을 쓰지 않고 G-1~G-5로 만든 내용을 `OutDir`의 기존 파일과 **줄 끝을 LF로 맞춘 뒤** 바이트 단위로 비교한다(Windows 체크아웃이 CRLF로 바꿀 수 있다). 같으면 종료 코드 0, 다르거나 파일이 없으면 종료 코드 1 |
| G-7 헤더 해시 | 헤더의 `sha256`은 입력 파일 전체의 SHA-256이다. 입력이 바뀌면 `-Check`가 실패한다 |

#### 8.2.2 손계산 (기대값을 구현이 아닌 규칙에서 얻었음을 보이는 풀이)

- **TC-08**(`ko-sample.tsv`, `-Count 7`): `a`(U+0061)와 `漢`(U+6F22)는 한글 음절 범위 밖이라 건너뜀 → `skipped=2`. `가`는 두 줄(900, 100)이므로 첫 줄(900)만 쓴다. 남은 문자와 값: 가 900, 나 700, 다 700, 라 500, 마 500, 바 300, 사 200, 아 200, 자 50(9개). 값 내림차순, 같은 값은 코드 포인트 오름차순: 가(U+AC00) 900, 나(U+B098) 700, 다(U+B2E4) 700, 라(U+B77C) 500, 마(U+B9C8) 500, 바(U+BC14) 300, **사(U+C0AC) 200**, 아(U+C544) 200, 자(U+C790) 50. 앞에서 7개 = 가, 나, 다, 라, 마, 바, 사(200 동률에서 U+C0AC < U+C544라 사가 들어가고 아는 빠진다). 코드 포인트 오름차순 출력: `0xAC00, 0xB098, 0xB2E4, 0xB77C, 0xB9C8, 0xBC14, 0xC0AC`. `selected=7`.
- **TC-09 (a)**(`ko-rank.tsv`, 문자 열 2, 값 열 1, `rank`, `-Count 3`): `a` 건너뜀. `다`는 순위 4와 5 두 줄 → 첫 줄(4)만. 남은 문자와 순위: 가 1, 나 2, 다 4, 라 6. 순위 오름차순 앞 3개 = 가, 나, 다 → `0xAC00, 0xB098, 0xB2E4`. **(b)**(`ko-order.txt`, `order`, `-Count 2`): `a` 건너뜀 → 가, 나, 다 순. 앞 2개 = 가, 나 → `0xAC00, 0xB098`.
- **TC-10**(`zh-sample.tsv`): 범위 U+4E00–U+9FFF. `a` 건너뜀. 문자와 값: 的(U+7684) 1000, 是(U+662F) 900, 不(U+4E0D) 900, 了(U+4E86) 800, 人(U+4EBA) 700, 一(U+4E00) 50(6개). 값 내림차순, 같은 값은 코드 포인트 오름차순이라 900 동률에서 不(U+4E0D)가 是(U+662F)보다 앞: 的, 不, 是, 了, 人, 一. `-Count 6`: 모두 포함, 코드 포인트 오름차순 `0x4E00, 0x4E0D, 0x4E86, 0x4EBA, 0x662F, 0x7684`(一 U+4E00은 범위의 하한이고 포함). `-Count 5`: 一이 빠져 `0x4E0D, 0x4E86, 0x4EBA, 0x662F, 0x7684`.
- **TC-11**: TC-08과 같은 입력에서 남은 문자는 9개 → 20개를 못 채움 → 종료 코드 1.
